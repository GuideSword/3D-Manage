## 4. Bug 修复阶段

实施过程发现 7 个问题，逐个修：

### 4.1 FAB 点击无反应
- **症状**：点悬浮窗没反应，FAB 本身可拖动
- **原因**：我写的 `App.js` 用 `global.__NAVIGATOR__` 跳转，**但从未给这个全局变量赋值**——`if` 永远 false，`handlePress` 是空函数
- **修法**：用 React Navigation 7 官方的 `createNavigationContainerRef` 模式，`navigationRef` 在 AppNavigator 创建并 export，App.js import 后用 `navigationRef.isReady()` 守卫

### 4.2 API Key 测试失败
- **症状**：点"测试连接"失败，但 Key 正确
- **根因 1**：默认 Base URL 是国际站 `api.minimax.io`，用户在国内需要 `api.minimaxi.com`
- **根因 2**：测试用 `client.models.list()`，MiniMax 文档没明说支持这个端点
- **修法**：
  - 默认 URL 改 `https://api.minimaxi.com/v1`
  - 测试改用最小化 chat completion（5 token 预算）+ 同时测 embedding
  - 返回结构化结果：LLM 和 Embedding 各自的 ok/error/status

### 4.3 API Key 没有"显示"功能
- **修法**：API Key 字段加 `👁/🙈` 切换按钮（`secureTextEntry` 状态切换）

### 4.4 "MiniMax 协议" 措辞不准
- **用户指出**：MiniMax **没有搜索模型**，"MiniMax 协议"指的不是搜索而是 embedding 端点的私有协议
- **修法**：UI 改 "📊 Embedding（MiniMax embo-01）"，hint 文案明确解释"协议"指 GroupId + texts/type

### 4.5 `embedProvider is not defined`
- **症状**：测试时 embedding 报 `embedProvider is not defined`
- **原因**：`routes/agent.js` 用了 `embedProvider.embed(...)` 但忘了 `require`
- **修法**：加 `const embedProvider = require('../agent/providers/embed');`

### 4.6  块吃掉 token
- **症状**：测试回复永远是 `<think>The user has sent</think>`（5 token 全被思考块占）
- **原因**：MiniMax M3 默认开启 thinking
- **修法**：测试调用加 `extra_body: { thinking: { type: 'disabled' } }`，并兼容剥离残留的 `<think>...</think>` 标签

### 4.7 流式响应：`Streaming not supported in this environment`
- **症状**：聊天报 "Streaming not supported in this environment"
- **原因**：`sseClient.js` 用 `fetch().body.getReader()`，**React Native 的 fetch 不支持 Web Streams API**——body 没有 getReader
- **修法**：用 XMLHttpRequest + `xhr.onprogress` 增量接收（XHR 是 RN 推荐的流式方案）
- **新文件**：`components/agent/sseClient.js` 整体重写，导出 `streamSSE(url, opts, onEvent)`

## 5. 部署阶段：端口 3001 EACCES

**最关键也最费时间的部署问题**：

### 5.1 现象
- 旧的 `node server.js` 在 3001 端口**输出全部正常**（"Server running" 打了），但**进程立刻退出**
- 我加了诊断 handler 后看到：`EACCES: permission denied 0.0.0.0:3001`
- 换 3002 也 EACCES，换 5000 就好

### 5.2 根因
**Windows 保留 2906-3005 + 3006-3105 端口段**（Hyper-V / WSL / Docker 容器预留）。`netsh interface ipv4 show excludedportrange` 能看到部分范围，但实际被占的端口比显示的更广。netstat 查不到占用者（因为是系统级保留），但 bind 时被拒绝。

### 5.3 修法
**改默认端口到 5000**——三处一致：
- `backend/server.js`：`PORT = process.env.PORT || 5000`
- `constants/index.js`：`PUBLIC_API_BASE_URL` 端口 + `getExpoHost` fallback 端口
- `start-project.ps1`：`$BackendPort = 5000`（默认参数）

## 6. 后台进程管理

工具沙箱 30 分钟超时问题，折腾了 4 种方案都失败：

| 方案 | 结果 |
|---|---|
| `Start-Process` 单独 | 子进程被父 shell 拽回 |
| `cmd /c start /B` wrapper | 同样被拽回 |
| WMI `Win32_Process.Create` | 进程秒死，无错误 |
| `schtasks /create`（计划任务） | `Access is denied`（需要管理员） |

**最终方案**：在用户自己终端里运行 `node server.js`，那个进程不归我管，能跑任意久。

## 10. 经验教训

1. **设计阶段要早暴露假设**：原计划用 Postgres + pgvector，幸亏 grilling 阶段让我去查代码现状，发现 `pg` 一直没启用，改成 SQLite 避免了大坑
2. **小工具的全局变量假设要明示**：我以为 `global.__NAVIGATOR__` 是"显然的约定"——其实根本不是。`createNavigationContainerRef` 是正经做法
3. **测试要多层验证**：测连接只测 LLM 不够，embedding 也是关键路径
4. **Windows 进程管理是真的坑**：`Start-Process` 不像 Linux 的 `nohup` 那样自动 detach。要么自己终端跑，要么注册成服务（需要 admin）
5. **遇到 EACCES 不要只看 netstat**：Windows 系统保留的端口 netstat 看不到，要 `netsh interface ipv4 show excludedportrange`
6. **用户的纠正要立刻执行**：用户指出 "MiniMax 没有搜索模型"、"应该说协议格式不是厂商名"、"JSON 集合不适用" 这些纠正都很准确，每次都让方案更扎实
