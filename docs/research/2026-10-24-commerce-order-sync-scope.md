# 电商订单同步：首期范围讨论

状态：已按用户最新决定暂缓，移出近期计划，等有自己的网店后再评估。尚未开始实现平台连接或本地采集功能；不再继续当前个人闲鱼账号的接入验证。以下保留此前调研与范围讨论，恢复时应重新核实店铺类型、权限及费用要求。

## 用户目标

原始目标是连接订单 API，在电商平台出现新订单后自动获取到本系统。首期目标为普通个人闲鱼账号，淘宝、拼多多等平台放在后续。用户已排除付费与第三方服务，当前改为评估免费官方能力或本地浏览器采集，尚未确定实现路线。

## 当前需要确认

- 已确认：普通个人闲鱼账号。不能要求用户已有天猫企业店或闲鱼定向合作方资质。
- 对应账号及应用能否取得官方订单读取权限；API 文档存在不代表当前账号具备资格。
- 用户已排除第三方服务商及付费订阅，闲管家候选路线停止推进。当前未注册、购买或授权任何服务。
- 在确定平台后，再确认“新订单”是所有下单，还是仅已付款订单。建议首期自动接收已付款订单，并保留平台支付状态。

## 建议首期流程（待讨论）

1. 若免费官方 API 权限成立，由管理员连接店铺；若采用本地采集，用户在普通浏览器登录官方页面，采集器读取本人可见订单。私人登录凭据不交给后端或聊天。
2. 提供手动立即同步、最后成功时间、失败原因和恢复入口。官方 API 方案可由后端持续同步；本地浏览器方案依赖运行采集器的电脑及有效页面会话，不能承诺电脑或浏览器关闭后继续采集。ERP 页面本身不必一直打开。
3. 以平台、店铺、平台订单号去重；保留平台来源、原订单号和必要的交易字段。订单号作为字符串处理。
4. 已配置商品/SKU 到本地模型的对应关系时自动建待审核订单；定制或未匹配商品先进入待匹配队列，确认模型、材质等生产参数后再转业务订单。
5. 平台交易状态和本地生产状态分别保存。退款、关闭等变化形成待处理提醒，不能覆盖已执行订单或自动撤销库存事实。
6. 若取得官方接口权限，选择增量拉取或消息触发查询；若采用本地方案，只按可访问页面的实际能力采集。都需要覆盖重复、遗漏和中断恢复，不能混用两者的能力承诺。

首期建议聚焦单向接单与状态读取；发货回传、自动退款、商品发布、聊天消息和跨平台库存同步留待后续明确需求。

## 官方接口同步方式（仅在取得相应权限后适用）

- 增量拉取：后端按平台允许的频率查询变更订单，并保存分页/时间游标。建议在取得所需权限后先实现这一版，便于排查和恢复。
- 消息触发加增量补偿：收到官方订单变更通知后查详情，另做定期补漏。延迟更低，但需要额外的消息权限和接收环境；取得对应权限后再启用。

以上选项都以目标店铺、应用类目及部署环境获得许可为前提，不预设普通个人号具备服务商接口权限。

## 首期验收目标

- 用获准店铺的一笔真实已付款订单验证“平台读取 → 后端接收 → 数据库保存 → 页面显示”，不以模拟接口宣称完成接入。
- 同一订单重复拉取、重复通知或超时重试，最多生成一个来源记录及一个本地业务订单。
- 未匹配模型的订单可见、可补齐信息，不产生虚假模型或静默丢单。
- 后端重启或同步中断后可以从持久化位置补拉；授权失效时页面显示原因和重新授权入口。
- 取消、退款等平台变化不会覆盖本地已执行的生产或库存事实。
- 前端、APP 响应和日志不暴露应用密钥或店铺访问令牌。

## 项目接入约束

- 目前关系型订单创建要求客户、订单行，且只允许草稿或待审核；现有表单对新行要求模型。外部商品信息不足时需要待匹配入口，不能生成虚假模型或客户资料。
- 本地订单金额按订单行计算。平台实付、优惠和运费要保留独立来源事实，不能把平台实付金额直接当作商品单价。
- 现有业务命令要求有效操作者、会话及幂等键；后台同步需要设计明确的服务执行身份，不能长期复用某个人的登录令牌或绕过审计。
- 目前关系型运行入口尚无通用店铺同步任务生命周期，需要给同步任务提供启动、停用和关闭机制。
- 项目以自部署为主；如果目标平台要求在指定云环境处理或存储订单数据，需要先解决部署兼容性，不能预设所有订单详情都可直接落到本地数据库。

## 官方接入资料

- 淘宝：[商家后台系统应用](https://developer.alibaba.com/docs/doc.htm?articleId=101564&docType=1&treeId=512) 的公开指南（2025-08-19 更新）对这一自研类目限定公司身份、具备开发能力的天猫卖家，并说明不支持淘宝集市卖家。因此不能据通用的 [自研商家接入指南](https://developer.alibaba.com/docs/doc.htm?articleId=120869&docType=1&treeId=794) 推断普通淘宝店能够申请这一类目；服务商 ERP 路线须另行核验。
- 闲鱼：[官方订单查询接口](https://developer.alibaba.com/docs/api.htm?apiId=50672) 列有卖家未通过招商及非当前卖家订单的准入错误，且标注需要授权、聚石塔内调用。[合作方服务端文档](https://open.goofish.com/doc/development/dev/server.html) 还明确其文档场景下的部署与存储要求。普通个人账号是否可接当前目标业务，需要实际核验。
- 平台接口与资格的进一步核验见 [官方 API 可行性调研](2026-10-24-commerce-order-api-feasibility.md)。

## 已排除的服务商路线（保留调研依据）

[闲管家自身操作手册](https://m.goofish.pro/app/operation.html) 第十一章说明可选择“我有自研系统”接入 ERP，并列出订单同步能力；第六章描述绑定账号后的新订单同步，以及绑定前订单的手动同步。这是服务商提供自研系统 API 方向的第一手资料，不能替代闲鱼官方对目标个人账号的权限确认。

进一步核验：服务商自己的 [接入教程](https://s.apifox.cn/35842026-8755-4ac7-a61e-9b07fbcac599/doc-9547461)（2026-10-21 修改）FAQ 8 明确称正常使用的个人卖家及鱼小铺均可接入；FAQ 3 和版本章节要求店铺有开放平台权益，ERP 专业版或铂金版可用，高级版不能创建应用。FAQ 9 提供首次绑定店铺七天试用说明，无沙箱。此为服务商第一手说明，并非已用用户账号验证成功，也不证明当前普通自研与服务商模式的权限、订购方式完全相同。

进入该候选路线前须验证：

1. 用户的普通个人闲鱼账号能否成功绑定并开通所需订单接口。
2. 能否读取用户在闲鱼 APP 自行发布的现有商品产生的新订单，而不只是通过服务商发布的商品订单。
3. 绑定前历史订单、退款及关闭订单的实际可读范围和接口字段。
4. 当前账号可用版本、订阅费用及自研系统调用权限；未核实前不报价或承诺免费。

以上为此前调研候选，现因用户“免费、无需第三方服务”的约束被排除，不再要求用户注册或试用。

## 免费本地方案的待验证事项

在未确认个人号可获免费官方订单 API 的情况下，检查官方网页版是否向个人卖家展示自己的订单。若登录后页面可读取所需字段，可以讨论运行在用户电脑上的本地采集器，将可见订单同步到自部署后端。这属于浏览器采集，不能标称官方 API 接入。

- 必须先看到目标账号的实际卖家订单页面，确认订单号、支付状态、商品、数量及金额的可读情况。
- 用户自行在官方页面完成登录；不要求将密码、验证码或登录凭据发到聊天。
- 只读取本人可见订单；遇登录失效、验证或页面结构变化时停止并显示原因。
- 自动同步仅在运行本地采集器的电脑开机、进程运行且登录有效时可用。单纯浏览器网页不能自行突破跨域及登录限制读取另一个站点。
- 采集器按订单号去重，来源交易状态独立保存，未匹配商品等待用户确认，不直接生成生产或库存操作。

目前没有基于真实登录订单页面完成字段读取验证，不承诺该方案已经可用。
