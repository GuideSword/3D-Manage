# 电商订单 API 接入可行性（官方资料核验）

项目状态：用户已决定暂缓电商接入，等有自己的网店后再评估。本文保留为历史调研，不代表当前开发计划；恢复时需重新核验当期平台规则和目标店铺权限。

核验日期：2026-10-24。前半部分引用淘宝/闲鱼官方资料，补充部分另列闲管家服务商自己的公开说明；两种来源不混同。未登录用户账号或开放平台控制台，未申请应用、授权、购买服务或调用真实订单。本文确认的是公开能力与准入限制，不代表本项目已获生产权限。

## 结论与推荐

淘宝、闲鱼均有官方订单能力，但首个平台应由实际账号可获得的权限决定，不能按 API 文档多少选择。淘宝普通集市店铺不能直接套用天猫商家自研路线；闲鱼普通个人号也不能预设为登录授权后即可获取全部订单。具体依据见下文。

将来恢复接入时，建议先确认经营平台、店铺主体、公司主体及现有开放平台权限，再做“一家店铺、单向接收已付款订单”的真实接口验证。当前不应承诺普通个人闲鱼账号已具备官方自动接单能力。生产排程、毛利、收款、预警等候选功能不再依赖本任务完成。

## 淘宝：订单能力明确，接入身份需要先验证

| 项目 | 已核实事实与来源 |
| --- | --- |
| 订单获取 | 官方《订单同步场景》（2025-09-30）给出 `taobao.trades.sold.get` 初始化、`taobao.trades.sold.increment.get` 增量、`taobao.trade.fullinfo.get` 详情的组合，也介绍消息服务和 RDS 订单推送；推送不等于任意自部署 HTTP 回调。[订单同步场景](https://developer.alibaba.com/docs/doc.htm?articleId=1029&docType=1&treeId=49) |
| 增量约束 | `taobao.trades.sold.increment.get` 标明需要授权，只能获取三个月内交易，单次修改时间区间不超过一天；实际额度、权限需查应用控制台。[增量 API](https://developer.alibaba.com/docs/api.htm?apiId=128) |
| 授权 | 官方 Web 授权流程为商家授权取 code，再由服务器换取 access token；仅能读取授权商家的数据。有效期及是否允许刷新取决于应用类型，不应统一假设可自动续期。[用户授权介绍，2024-09-25](https://developer.alibaba.com/docs/doc.htm?articleId=102635&docType=1&treeId=512) |
| 商家自研 | 2025-08-19 更新的文档要求公司身份、有开发能力的天猫卖家、自用店铺及聚石塔；明确淘宝集市卖家不支持该类目，推荐服务市场订购应用；要求提供自研 OMS/ERP 软著及产品资料。[商家后台系统应用](https://developer.alibaba.com/docs/doc.htm?articleId=101564&docType=1&treeId=512) |
| 服务商路线 | 官方存在企业 ERP/进销存应用类目，但公开规则更新时间为 2016-10-27。可作为企业认证、类目审核存在的证据，不能将旧文中的注册资本、年限、价格条件当作 2026 年可获批承诺；需实际控制台及平台确认。[ERP/进销存类目规则](https://developer.alibaba.com/docs/doc.htm?articleId=101615&docType=1&treeId=512) |
| 敏感信息 | 官方方案要求订单消费者信息脱敏，采用 OAID，本地不允许存储明文消费者敏感数据；姓名、电话、详细地址不能按普通客户资料直接落库。解密权限需另行核验。[订单敏感信息处理方案，2024-07-31](https://developer.alibaba.com/docs/doc.htm?articleId=120189&docType=1&treeId=1) |

对本项目的含义：如果是普通淘宝店，先核实是否有合适的已批准服务商或可申请应用路线；如果是符合条件的天猫企业自研店铺，再验证自研应用。两者都不能只提供 AppKey 就视为可用。

## 闲鱼：必须区分普通交易、SaaS 服务商和专属业务

| 项目 | 已核实事实与来源 |
| --- | --- |
| SaaS 订单详情 | `alibaba.idle.isv.order.query` 按订单号取详情，官方标注需要授权、聚石塔内调用；错误码 `TOP_NOT_SELLER` 表示非当前卖家订单不可读，`TOP_SELLER_NOTALLOW_ACCESS` 表示卖家未通过闲鱼招商，要求联系运营报名。这是不能将普通号授权等同于可读订单的直接依据。[SaaS 订单查询](https://developer.alibaba.com/docs/api.htm?apiId=50672) |
| 增量候选 | `alibaba.idle.isv.order.rate.query` 提供分页及订单修改、追加评论时间区间，返回订单 ID、状态和更新时间；需要授权、聚石塔内调用。它证明存在服务商增量查询候选，尚不能证明我们获准读取普通个人卖家的所有交易。[卖家订单及评价查询](https://developer.alibaba.com/docs/api.htm?apiId=70250) |
| 卖家关系绑定 | `alibaba.idle.user.permit` 明示用于闲鱼卖家与服务商关系绑定、数据分发、授权校验及消息通知鉴权；需要授权、聚石塔内调用。[用户 AppKey 授权](https://developer.alibaba.com/docs/api.htm?apiId=56250) |
| 消息通知 | `idle_topisv_TradeNotice` 在官方“闲鱼已验货”类目中，说明订单变化时点对点通知合作方，含订单号、卖家和状态。页面“不需要授权”的标签不能解释成任意开发者可订阅全部卖家订单；接收资格仍需平台确认。[订单变更消息](https://developer.alibaba.com/docs/topicDetail.htm?apiId=2079) |
| 隐私 | 官方另有 `alibaba.idle.isv.order.decrypt.privacy`，标注需要授权、聚石塔内调用。详情示例包含地址、手机号和 OAID 不代表生产环境一定返回可长期存储的明文。[收货信息隐私解密](https://developer.alibaba.com/docs/api.htm?apiId=75208) |
| 验货宝 | `alibaba.idle.appraise.order.query` 明确供鉴定商获取订单状态，需授权、聚石塔内调用；这是验货宝服务商能力，不能代替普通闲鱼卖家的订单同步。[验货宝订单详情](https://developer.alibaba.com/docs/api.htm?apiId=50520) |

另有**小程序合作方**路线：公开《快速接入》写明定向邀请、企业主体一致，订单能力需申请 B 端 AppKey；《服务端接入》列出订单查询及 `idle_autotrade_OrderStateSync`/`idle_autotrade_RefundSync`，并要求该场景服务端及订单、用户数据存储在聚石塔内。该路线涉及合作方商品、业务标识和权限申请，不能推导它覆盖普通个人卖家的既有交易；也不能把小程序的全部准入规则直接推广为所有闲鱼 API 的规则。[小程序快速接入](https://open.goofish.com/doc/quick-start.html)、[合作方服务端](https://open.goofish.com/doc/development/dev/server.html)。

本次未在可公开读取的官方资料中核实“普通个人闲鱼账号可直接申请自研 ERP 并读取全部日常订单”的通道。搜索没有找到不等于该能力绝对不存在；应由目标账号在官方控制台、招商/开放平台支持处确认。

## 补充：用户为普通个人闲鱼号，可继续验证闲管家中转路线

用户后续已确认使用普通个人闲鱼账号。因此将“闲鱼 → 闲管家服务商 → 本项目”列为可验证候选，不能把官方直连资格未确认解释成个人号不存在任何 API 接入路线。

### 服务商自己的公开承诺

闲管家《接入教程-服务商模式》于 **2026-10-21** 修改，其常见问题明确写到：正常使用的个人卖家、鱼小铺及企业店铺可以接入；接口生效于账号下具有开放平台权益的店铺，需 ERP 专业版或铂金版，高级版不能创建应用。首次绑定的店铺提供七天试用，无沙箱或测试账号；店铺授权有效期半年，过期须重新授权。自用应用与升级后的服务商应用、对应订购渠道存在区别，不应为了单店自用直接照搬多商家服务商订购流程。[闲管家接入教程及 FAQ](https://s.apifox.cn/35842026-8755-4ac7-a61e-9b07fbcac599/doc-9547461)。

其操作手册第十一章给出“我有自研系统”入口和订单同步至 ERP 的说明。第六章区分绑定后订单同步与绑定前订单的手动同步；该说明未明确承诺用户通过闲鱼 APP 发布的全部既有商品，其新订单都能由自研应用 API 读取。[闲管家操作手册，第六及十一章](https://m.goofish.pro/app/operation.html)。

**来源边界：**`goofish.pro` 是这里核验的闲管家服务商网站，不等同于闲鱼 `goofish.com` 官方域名；上面的 Apifox 文档署名闲管家开放平台并链接其 `cdn3.goofish.pro` SDK，属于服务商第一手说明。它证明服务商公布了个人号接入方案，不等于闲鱼官方对该服务的独立背书，也不等于当前用户已通过资格验证。

### 仍须登录目标账号才能确认

1. 普通个人号当前是否可成功绑定，是否需要额外类目、经营身份或权限审核；单店自用能否创建并上线进销存应用。
2. **订单覆盖：**分别读取“既有闲鱼 APP 发布商品产生的新订单”“绑定前旧订单”“服务商发布商品产生的新订单”，确认 API 与后台手动同步范围一致。现有资料不能证明仅限服务商发品，也不能保证所有日常订单均覆盖。
3. 当前账号订购页提供的版本、按店铺计费规则、实际金额、试用及订单 API 权益；本文不报价、不购买，不把试用等同永久免费。
4. 自用应用可获得的 AppKey、签名、订单列表/详情/回调协议、调用配额、允许保存的订单字段、数据存储和准出要求。`open.goofish.pro` 根路径本次返回 404，不能据猜测的接口地址开始实现。

建议下一步只在用户接受第三方服务及可能订阅费后，核验上述资格和订单范围；通过后按“一店、单向接单、已付款订单、真实后端写入”范围设计实现。无需先把普通个人号升级为企业或切换淘宝来证明可行。

## 进入实现前的最小验证

1. 确认用户实际是普通闲鱼个人号、通过招商的闲鱼商家/服务商、淘宝集市店还是天猫企业店；只接自己的店还是作为产品服务其他商家。
2. 在目标应用中确认订单列表/增量、详情、消息权限及可授权卖家范围；实际读取一笔目标卖家的测试订单，证明普通交易确实在授权范围内。
3. 确认指定云部署、数据库存储与数据准出规则，解决本项目自部署数据库如何接收允许的数据；不能预设订单原始响应可全部写回本地。
4. 在批准范围内设计后台同步：令牌服务端保管、时间游标与重叠补拉、平台+店铺+订单号去重、消息重复与延迟处理、失败可重试。平台交易状态与本地生产状态分离。

以上为建议的验证顺序，不是平台已批准的应用方案；尚未验证登录后可见的当期审核要求、费用、配额和最终字段。
