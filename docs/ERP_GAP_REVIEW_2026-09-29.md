# 3D 打印 ERP 功能差距复核

复核日期：2026-09-29。依据为当前工作区代码，而非 README 的能力描述或规划勾选。本文为调查报告，新增模块尚未实施。

## 当前结论

当前项目提供订单记录与状态、模型资料及受保护附件、耗材与批次、库存流水、团队权限、审计、导入导出、可选 AI 和自托管。调查时订单、模型、耗材、批次虽有更新接口，页面修改流程仍缺失；本次已补齐这些编辑流程及普通用户姓名编辑，并完成自动化及 Web 界面验收。用户角色与启停原本已能修改。

库存 P0 已有公共服务、期初流水、严格毫克数量、幂等回执、批次版本检查、引用删除保护和历史异常标记；本次复核运行 npm run verify:erp，16/16 通过。不能将这些能力列为“完全缺失”，但上线与人工验收状态仍须核对。

经营链路尚未闭合：订单不能追踪到打印任务、具体设备、合格产出、分批交付、收款以及实际成本。现有 completed 状态不能代表已生产、已交付或已收款。

## 建议实施顺序

先修现有表单修改，再沿用仓库已有路线图：主数据与关系存储 → 生产/设备/质检 → 报价与成本 → 采购 → 交付/结算/经营报表。设备联网和自动排产放在经营链路稳定之后。

完整 ERP 首版的验收应是一笔订单从报价、确认、生产、领料、失败补打、质检、交付到收款和毛利均可追溯；一笔采购从下单、收货、批次到付款均可追溯。仅新增菜单或状态不能作为模块完成依据。

对应现有文档：[ERP 改造设计](ERP_TRANSFORMATION.md)、[分阶段路线图](superpowers/plans/2026-09-27-vertical-erp-roadmap.md)。本报告补充“编辑功能优先”并复核当前差距，不把 P1–P6 规划当作现成功能。

按重要程度与依赖细化的后续计划：[ERP 优先级实施计划](superpowers/plans/2026-09-29-erp-priority-plan.md)。
