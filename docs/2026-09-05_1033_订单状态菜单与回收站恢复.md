## 2. 完整改动清单

### 2.1 长按修改订单状态（基础功能）

**文件**：`screens/OrdersScreen.js`

- `OrderCard` 的外层 `TouchableOpacity` 加 `onLongPress`，420ms 阈值
- 加 `updatingId` state，长按时弹出操作菜单
- 选中后先本地乐观更新订单状态，再发 `ordersAPI.updateStatus`
- 卡片右上角 badge 在更新中替换为同色 spinner（位置不抖）
- 删除按钮独立加 `onLongPress` 的 `stopPropagation`，避免误触

### 2.2 自定义 ActionSheet 替代系统 Alert

**新文件**：`components/StatusActionSheet.js`

4 个关键点：

1. **按钮化样式** — 每行：状态色圆点 + 状态名 + 右侧指示（当前/退级/重开/普通箭头）
2. **点外部退出** — `Modal transparent` + 全屏 `Pressable` 遮罩 + `onRequestClose` 接安卓返回键
3. **配色圆角** — `RADIUS.xl`（14px）顶角、`SHADOWS.floating` 投影、状态色派生 `hexToRgba` 透明背景
4. **水波纹动效** — `Pressable.onPressIn` 抓 `locationX/Y` → 渲染 260×260 圆，`scale 0.35→2.6` + `opacity 0.28→0`，540ms `Easing.out(quad)`；外层 `scaleAnim` 0.985 微缩反馈

入场动画：背景 220ms 淡入 + 弹出层 300ms `cubic-out` 上滑 + 0.98→1 缩放，全部 `useNativeDriver: true`

### 2.3 退级确认机制

**新文件**：`utils/orderStatus.js`

- 线性流定义 `FLOW_ORDER`（draft → pending_review → in_progress → completed），`cancelled` 是旁路
- `isDowngrade(from, to)`：to 在线性流中位置比 from 靠后
- `isReopen(from, to)`：从 completed 退回任何非 cancelled 状态（"重新打开"）
- `getDowngradeMessage` / `getDowngradeTitle`：4 条通用影响 + 重新打开场景加 1 条

**UI 表现**：
- 退级选项右侧出现"**退级**"橙色 pill + 边框描边
- 重新打开选项"**重开**"红色 pill
- 点击 → 二次确认 Alert → 确认后提交
- 水波纹颜色与 pill 配色一致，让按压反馈本身传达风险

### 2.4 后端状态机放宽

**文件**：`backend/routes/orders.js`

```js
// 改前：completed 和 cancelled 都是空数组（终态）
// 改后：
const allowedTransitions = {
  draft:          ['pending_review', 'cancelled'],
  pending_review: ['in_progress', 'cancelled', 'draft'],
  in_progress:    ['completed', 'cancelled', 'pending_review', 'draft'],
  completed:      ['in_progress', 'pending_review', 'draft', 'cancelled'],
```

**前端同步**：`utils/orderStatus.js` 的 `ALLOWED_TRANSITIONS` 镜像表（注释要求保持一致），`isAllowedTransition` / `isTerminalStatus` / `isRestorable` / `getRestoreTarget` 工具函数。

**UI 防线**：不允许的转换在前端就标"🔒 不可用"，根本不让点。`cancelled` 订单在 `OrderCard` 上不上 `onLongPress`，避免空响。

## 4. 关键设计决策

| 决策 | 理由 |
|---|---|
| 退级也允许 | 用户明确要求"从执行中退回到待审核是可行的"；并补充"其他的退机操作也要跟上" |
| 用 `isAllowedTransition` 同步前后端 | 单一来源原则；后端改规则时前端同时跟着改，不会出现"前端能选、后端拒绝"的诡异状态 |
| 退级用系统 Alert 二次确认 | 简单二选一，Alert 是项目里既定模式；不必为确认步骤再造组件 |
| 恢复操作用自定义面板 | 跟普通状态选择是两种交互语义，自定义 UI 避免混淆 |
| 不动 OrderDetailScreen 的 `getAvailableActions` | 详情页快捷按钮保持"提交审核/开始执行/标记完成/取消订单"4 个正向流程；退级走长按菜单，两条路径互补不冲突 |
| `cancelled` 仍走 `ordersAPI.updateStatus` | 后端规则已经统一；前端不另开路由，少一份代码 |
| 旧远端脚本移到 `_deprecated_remote_assets/` | 删文件受限，移到子目录既不干扰工程又可恢复 |
