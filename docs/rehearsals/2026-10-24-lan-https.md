# 内网 HTTPS 与下载密码权限验收

用户已确认仅限制模型下载密码；账号自助修改登录密码保留。用户核对根证书 SHA1 后在 Windows 安全警告中点击“是”。

## 已交付

- 根目录 `配置内网HTTPS.bat`：固定版本、固定 SHA256 的官方 mkcert，Windows PowerShell 5.1 执行，签发明确 IP/DNS 的部署证书；不需要域名。
- CA 私钥仅在 `runtime/tls/ca`；应用只读挂载 `runtime/tls/server`。设备分发目录 `runtime/tls/clients` 仅含公开证书、指纹和信任入口。
- `-TrustCurrentUser` 显式安装当前用户信任；重复安装同一证书不会再次弹窗。`-Apply` 备份 .env，保留现有卷，重建并等待应用健康。续签使用同一 CA，并强制重建 app 加载新服务证书。
- HTTPS 与原 HTTP 模式分别健康检查，HTTPS 使用 CA 校验证书及 localhost，不跳过验证。现有后端启动脚本能识别 HTTPS。
- 模型下载设置说明区分下载密码与登录密码，普通成员看不到修改入口；服务端 owner 检查保留，权限矩阵实测通过。

## 实际验收

- `tests/ops/lan-https.verify.ps1 -MkcertPath <固定版本exe>`：真实 Windows PowerShell 5.1 首次签发、重复保留 CA、设备目录白名单、错误指纹拒绝、错误地址拒绝、准备模式不改 .env 通过。fixture 自动清理，不安装测试 CA。
- `LAN_HTTPS_TEST_DIR=<fixture>/runtime/tls/server node --test tests/backend/lan-https.test.cjs tests/backend/model-downloads.test.cjs tests/backend/model-downloads-legacy.test.cjs tests/backend/erp-server-runtime.test.cjs`：12 通过、0 失败，1 个需要隔离 PostgreSQL 环境变量的服务器模式用例跳过。下载服务、HTTP角色矩阵及旧存储接口测试均实际执行；未以跳过项宣称已验收关系 PostgreSQL。
- 真实 TLS 用例证明：CA 与 IP/主机名正确时成功；缺少 CA、错误主机名、HTTP 或伪造 X-Forwarded-Proto 被拒绝。HTTP 安装的健康检查保持可用。
- staff/viewer 直接 PUT 策略（改密、关闭保护）均 403；提交 role=owner 不能提权。Owner 缺少或输错下载密码同样被拒绝，正确密码可下载，轮换后旧授权失效；状态与修改响应不回显密码/哈希。
- Expo Web 导出通过；Windows 原有后端启动脚本 `-Mode Start -NonInteractive` 实际通过，输出 HTTPS 地址；Docker app healthy。
- Edge 无 `ignoreHTTPSErrors`：直接访问内网 IP HTTPS 200；本地 Web `http://localhost:8081` 跨域调用 `https://192.168.0.33:5800/api/system/info` 200，零 pageerror。未登录 PUT 策略返回 AUTHENTICATION_REQUIRED 而非 HTTPS_REQUIRED，未修改正式下载设置或密码。
- 正式服务端口 5800；serverId `f5942634-5fdd-4964-abc6-3971b1787c0b` 前后一致。业务计数前后一致：users 1、models 3、orders 1、materials 2、auditLogs 68，其余库存及上传回执集合均为 0。
