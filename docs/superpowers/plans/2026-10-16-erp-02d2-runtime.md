# ERP 02D2：业务运行入口与维护保护实施计划

> 沿用已批准阶段02设计、02D1推进评估和总计划逐项执行；不派发子代理。先完成可隔离验证的运行绑定，再接正式server；本计划不等于正式切换授权记录。

**Goal:** 每次启动只绑定一个事实源，不加载另一个来源的初始化/写工具；后续接入维护停写、系统入口和Owner主机恢复。

**Architecture:** 先创建不读环境变量的 `createBusinessRuntime`，通过两种延迟factory选择一种router及关闭动作。PG启动前复用02D1 inspector；运行中模式或身份变化立即拒绝后续请求，不热切换或自动回落。其后把server顶层的旧store/AI初始化迁入legacy factory，再补齐关系系统入口和事务内维护屏障。

**Tech Stack:** Express、pg、PostgreSQL16、现有领域router、Node test和隔离Docker。

## 已确认的接线风险

- `backend/server.js` 当前加载即调用 initializeStore/initStorage/getDb，并挂载全部旧路由；只在底部替换订单router仍可能先写旧store。
- `middleware/auth.js` 从旧store核验角色；files/oss/agent路由不能原封不动挂到关系模式。agent/orchestrator和dbBridge还直接引用旧store，关系模式需要后续适配。
- 关系Router已有登录/权限、主数据/订单/库存等接口，但组织设置、首页统计和文件/AI完整链路尚未补齐。不得将当前router当成可发布的全量替代。
- 请求前检查模式无法代替事务内维护锁。02D2必须继续完成在途写排空及HTTP/CSV/AI共用的维护屏障；本包前一项不宣称已能安全热切换。

- [x] 模块只import connection与storageMode；配置显式传入，不import旧store/AI/route，不读取环境。将下面算法落实为同一模块内的实际函数，资源所有权明确：

```js
const error = (code, message, cause) => Object.assign(new Error(message), { code, status: 503, ...(cause ? { cause } : {}) });
async function createBusinessRuntime({ driver, connectionString, expectedServerId, factories } = {}) {
  const normalized = typeof driver === 'string' ? driver.trim().toLowerCase() : '';
  if (!['file', 'postgres', 'pg'].includes(normalized)) throw error('BUSINESS_RUNTIME_CONFIGURATION_INVALID', '业务存储配置无效');
  if (!factories || typeof factories.legacy !== 'function' || typeof factories.relational !== 'function') throw error('BUSINESS_RUNTIME_CONFIGURATION_INVALID', '业务运行入口配置无效');
  let pool, handle;
  try {
    if (normalized !== 'file') pool = await createBusinessPool({ connectionString });
    const binding = pool ? await inspectBusinessStorage(pool, { expectedServerId }) : { mode: 'legacy', schemaVersion: 0, installation: null };
    handle = await factories[binding.mode]({ pool, installation: binding.installation });
    if (!handle || typeof handle.router !== 'function' || (handle.close !== undefined && typeof handle.close !== 'function')) throw error('BUSINESS_RUNTIME_CONFIGURATION_INVALID', '业务运行入口配置无效');
    let closed = false, closing;
    const close = () => {
      if (!closing) {
        closed = true;
        closing = Promise.resolve().then(async () => {
          try { await handle.close?.(); } finally { await pool?.end(); }
        });
      }
      return closing;
    };
    const router = async (req, res, next) => {
      try {
        if (closed) throw error('BUSINESS_RUNTIME_CLOSED', '服务正在维护，请稍后再试');
        if (pool) {
          const current = await inspectBusinessStorage(pool);
          if (current.mode !== binding.mode || current.schemaVersion !== binding.schemaVersion
            || current.installation?.serverId !== binding.installation?.serverId) throw error('BUSINESS_RUNTIME_CHANGED', '服务配置已变化，请稍后重试');
        }
        return handle.router(req, res, next);
      } catch (cause) {
        return next(error(cause.code || 'STORAGE_UNAVAILABLE', '服务器存储暂不可用，请稍后再试', cause));
      }
    };
    return { mode: binding.mode, router, close };
  } catch (failure) {
    try { await handle?.close?.(); } finally { await pool?.end(); }
    throw failure;
  }
}
```

- [x] 对关闭期间仍在等待PG核验的请求，核验后再次检查closed，不能在关闭后调用router。factory或校验抛出时保留原始异常，清理失败作为附加信息，不能掩盖原始错误。异步router拒绝须进入next，不能成为未处理Promise；实现时使用await调用。
