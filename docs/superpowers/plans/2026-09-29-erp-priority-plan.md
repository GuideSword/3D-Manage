## 1. 排序原则

1. **先处理影响日常使用的问题。** 编辑功能和库存一致性已有代码，优先完成真机、升级和发布验收，让用户实际用到。
   AI 聊天意外退出后无法续接也属于日常使用问题；复用已有服务端会话与分层记忆，在关系库迁移前补齐恢复入口。
2. **先保证数据可信，再增加业务模块。** 外键、事务、精确金额、版本和权限虽然不是新菜单，但必须早于采购和结算落地。
3. **先闭合 3D 打印生产过程。** 能记录设备、打印任务、实际耗材、失败补打和合格产出，才有可信成本与交付依据。
4. **再闭合经营过程。** 报价、采购、交付、收付款分别有单据，不能用一个订单状态代替所有业务事实。
5. **最后做自动化和扩展。** 首版使用单组织、默认人民币、单仓库、人工排程；联网设备、自动排产、多仓库等另行安排。

下表中的序号是默认执行顺序，“紧急/高/中/后续”是重要程度，原路线图 P0–P6 是已有阶段编号，三者不混用。高重要程度不代表可以绕过前置依赖立即开工。

## 3A. 01A：AI 聊天会话续接

**实现基础：** 复用 `backend/db/agent.js`、`backend/routes/agent.js` 的会话接口及现有[分层记忆设计](../specs/2026-09-13-agent-layered-memory-design.md)。最近 10 轮、滚动摘要和 8,000 token 输入预算继续保留；`AgentChatScreen.js` 已补齐历史读取、重开恢复、草稿和主动重试，服务端保留已接收的中断消息。

- [x] 在 AI 助手入口恢复当前账号上次会话，并提供会话列表、打开旧会话和新建会话；服务端验证会话归属，切换账号或服务器时不展示其他账号内容。
- [x] 从服务端加载已保存消息，显示清楚已完成与中断的轮次；同一会话继续发送时始终传回原 `conversationId`，不因页面重建静默新建会话。

- [ ] 记录切片/G-code 的文件版本、切片工具信息、预计耗材和预计机时，允许人工录入。
- [ ] 订单确认和生产下达时固定规格快照；参数或文件变更创建新版本，而不是覆盖在制任务。
- [ ] 对历史缺失规格标记“待补全”，保留旧文件和描述，不自动假定新版本适用。

**验收样例：** 模型从 v1 更新至 v2，原工单仍使用 v1；补打默认沿用原规格，改规格需显式记录。

**完成门槛：** 生产规格可重现、可追溯，任何文件和参数编辑不会静默改变既有生产任务。

## 6. 04：设备、生产工单和人工排程

**目标：** 将订单项目转成可执行任务，明确数量、设备、负责人和时间。

**入口：** 订单详情、模型版本、权限与导航；新增 `backend/modules/production/`，设备、工单和排程页面。

- [ ] 建立设备档案：型号、工艺/尺寸/材料能力、启用状态和维护状态。
- [ ] 由订单行下达生产任务，记录规格快照、数量、负责人、优先级和交期，限制重复/超量下达。
- [ ] 提供设备队列和人工时间分配，事务内拒绝同设备时段重叠与维护设备排程。
- [ ] 实现开始、暂停、恢复、取消动作，展示独立生产进度和逾期任务。
- [ ] 将订单商业状态与工单生产状态分开；订单 completed 不自动产生合格数量。

**验收样例：** 一笔 10 件订单可拆为 6 件、4 件两个任务；同一设备的重叠时段被拒绝；取消工单不删除原记录。

**完成门槛：** 订单行到工单、设备和排程可追溯。04 只完成任务管理，必须结合 05 后才能宣布生产闭环完成。

## 7. 05：实际耗用、打印结果和质检闭环

**目标：** 记录材料真正消耗在哪次打印，区分报工数量、合格数量、失败和补打。

**入口：** `backend/services/inventory.js` 与关系库库存服务、生产领域、报工/质检页面、订单详情。

- [ ] 建立任务级批次预留，展示现存、未领预留、可用数量；预留本身不扣库存。
- [ ] 实现领料和退料，保存任务、批次、来源单据和操作者；取消释放未领预留。
- [ ] 建立每次打印尝试，记录设备、开始/结束时间、实际机时、数量和失败原因。
- [ ] 实现报工、质检、不合格处置和补打；补打关联原任务和失败尝试。
- [ ] 限制质检数量不超过报工量，累计有效产出不超任务量；保留失败耗材和机时。
- [ ] 验证并发领料、超时重试、退料、部分完成、在制取消、失败补打及事务失败回滚。

**验收样例：** 批次 1000g，预留 300g 后领用 200g：现存 800g、未领预留 100g、可用 700g。失败耗材 100g 后补打再耗 100g：实际消耗 200g，成品报废不再次扣同一份原料。

**完成门槛：** 订单行 → 工单 → 打印尝试 → 质检 → 耗材流水形成可核对链路，合格产出可供后续交付。

## 8. 06：报价和成本

**目标：** 报价有计算依据，生产后能比较预计成本与实际成本。

**入口：** 订单金额服务、生产与库存服务、设备费率；新增 `backend/modules/costing/`、报价与成本分析页面。

- [ ] 配置耗材、设备机时、人工、后处理、损耗、外协及加价规则，明确单位、币种和精度。
- [ ] 建立报价单、人工调整和确认转订单；保存价格/规格快照，防止重复转换。
- [ ] 从领退料、打印尝试和额外费用生成实际成本，来源唯一；失败机时与耗材计入成本。
- [ ] 区分预计、暂估和已核对成本；历史批次无成本时标记“未知”，允许有依据的期初成本核对。
- [ ] 控制成本/利润字段权限，覆盖接口、导出与 AI，不能仅隐藏客户端文字。

**验收样例：** 报价拆出材料、机时和人工明细；退料按原成本回转；失败后的补打增加实际成本；成本未知时不显示确定毛利。

**完成门槛：** 每项成本都有来源且不重复。07 交付采购批次成本后完成实际成本来源复核，09 再完成经营结算口径；不将“已有报价公式”视为利润核算完成。

## 9. 07：采购和到货入库

**目标：** 从向供应商下单到形成库存批次与成本可追溯。

**入口：** 供应商/材料/仓库主数据、库存与成本领域；新增 `backend/modules/purchasing/`、采购/收货/退货页面。

- [ ] 建立采购草稿、确认、取消余量，保存供应商、规格与价格快照。
- [ ] 实现分批到货、验收及拒收，限制超量收货；收货单、批次、库存、成本同事务提交。
- [ ] 记录每个批次的采购成本和来源，关联 06 的实际耗材成本。
- [ ] 实现采购退货，限制原收货数量和可用库存；保留反向单据和原因。
- [ ] 接入待到货数量与采购进度，为 09 的应付建立确定来源。

**验收样例：** 采购 2000g，分两次各验收 1000g，只增加 2000g；重试不重复入库；已领用的库存不能通过整单退货变成负数。

**完成门槛：** 采购行 → 收货 → 批次 → 库存/成本可对账；此时未实现付款分配，不宣布采购财务关闭已完成。

## 10. 08：交付和售后

**目标：** 记录实际交付数量，支持部分发货、退回和返工。

**入口：** 订单详情、生产质检；新增交付领域和交付/退货页面，资金关联留给 09。

- [ ] 建立交付单，记录订单行、数量、物流、交付时间和经办人。
- [ ] 支持分批交付，累计净交付不超过可交付的合格产出。
- [ ] 退回关联原交付，记录数量、原因和检查/返工/报废处置，不仅修改订单状态。
- [ ] 售后返工关联原订单和生产记录；区分返工、成品报废和额外原料耗用。

**验收样例：** 10 件订单先产生 6 件合格品，只能交付至多 6 件；后续再交付 4 件；退回 1 件能追溯原交付和处置。

**完成门槛：** 已生产、已交付、未交付、退回数量分别有真实单据依据，退款由 09 的资金单据处理。

## 11. 09：收付款和经营结算

**目标：** 回答每笔订单/采购“应收应付多少、已收已付多少、还差多少”。

**入口：** 订单确认、采购验收、交付/退货和成本领域；新增 `backend/modules/settlement/`、应收应付与收付款页面。

- [ ] 建立新订单确认生成应收、采购验收生成应付的唯一来源；交付状态不替代收款状态。
- [ ] 支持定金/尾款、分次收付款、预收/预付与资金分配，限制超额分配。
- [ ] 实现贷项、退款和冲销，保存来源、原因及反向单据，不直接改掉原资金记录。
- [ ] 历史订单仅生成经核对的期初未结余额；旧 completed 不自动认定已收款或已交付。
- [ ] 建立业务关闭条件，核对交付、资金和费用余额；成本完整时展示订单管理毛利。
- [ ] 验证部分支付、取消订单、采购退货、退款、跨单分配和失败回滚，补齐财务动作权限。

**验收样例：** 订单 500 元，先收 200 元再收 300 元，应收余额依次为 300、0；退货、退款有独立记录，重复请求不重复确认或收款分配。

**完成门槛：** 一笔订单与一笔采购的生产/库存、交付、资金和成本全流程对账通过。管理核算与专业总账分开，首版不建设税务申报或完整总账系统。

## 12. 10：经营报表和提醒

**目标：** 在已有真实单据上提供可行动的信息，而不是只显示订单总数。

**入口：** `screens/HomeScreen.js`、`components/home/`、现有统计接口；新增 `backend/modules/reporting/`。

- [ ] 生产完成后先上线低库存、设备维护、工单逾期提醒和失败率，不必等待所有财务报表完成。
- [ ] 交付/结算完成后增加未交付、逾期应收、应付、净收付款、订单成本与毛利。
- [ ] 定义设备利用率、准时交付率、失败率的分母、时间范围和异常口径，支持追溯至来源单据。
- [ ] 明确币种、时间区间、历史待核对和成本完整性，避免将暂估利润显示为已确认结果。
- [ ] 使报表与导出、AI 查询遵循同一权限和同一计算口径。

**验收样例：** 点击报表中的材料消耗或未收款金额可定位明细；相同时间条件下报表与单据对账；未知成本不计成 0 元成本。

**完成门槛：** 指标可解释、可核对，提醒指向具体任务或单据。设备利用率/失败率等功能可提前随 05 发布，这是默认顺序中允许的例外。

## 13. 11–12：首版稳定后的扩展

**11：AI 和设备只读接入。** 增加经营查询、异常解释、确认后的草稿执行，以及设备状态、队列、运行记录同步；事件必须去重，人工记录与设备记录冲突需核对。AI 复用业务服务和敏感字段权限。

- [ ] 每项扩展先说明具体用户问题、依赖、收益和验收用例，再生成专项设计与子计划。
- [ ] 保持人工业务入口可用，集成断开时不能破坏库存、生产和结算事实。

**完成门槛：** 按专项验收，不用一项扩展的成功代表其他扩展完成。
