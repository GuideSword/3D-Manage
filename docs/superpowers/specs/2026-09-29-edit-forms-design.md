# 业务表单修改功能设计

日期：2026-09-29。状态：用户已确认范围，业务代码已实现；自动化及 Web 界面验收通过，手机真机与发布待办。

## 1. 问题与目标

订单、模型、耗材和库存批次的 PATCH 接口以及客户端更新方法已存在，但业务详情页没有完整编辑入口，新建页面只调用 create。用户不能完成“打开原记录 → 修改 → 保存 → 看到更新结果”。此外，订单与耗材归一化使用 `payload.notes || existing.notes` 等写法，显式清空字段会恢复旧值。

本次目标是补齐现有模块的修改流程，沿用现有布局和角色规则。不在本次修复中建设生产、采购或财务模块。

## 2. 方案比较

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 复用现有新建表单，增加编辑模式（推荐） | 字段与校验共用，现有体验一致，交付范围集中 | 需要区分加载、新建、修改和附件处理 |
| 单独创建全部编辑页面 | 编辑逻辑独立 | 重复布局与校验，后续容易出现字段差异 |
| 在列表上逐字段即时保存 | 少量字段操作快 | 不适合订单多行和关联字段，易误保存 |

推荐第一种。批次没有独立的新建资料表单，增加专用批次编辑页；用户姓名使用现有用户管理页内的编辑弹窗。

## 3. 范围与交互

### 订单

- 详情页提供“编辑订单”，将 orderId 传入复用表单。标题、按钮、成功和失败文案区分新建与修改。
- 获取当前订单后回填客户、币种、交期、备注和全部订单行。订单行保留已有 ID、模型名称以及表单未呈现的附加字段。
- 编辑数量、单价或增删行后重算行小计与合计。自定义颜色、历史材质和未在当前选项列表中的模型仍能呈现原值，不能因编辑客户资料丢失旧订单行。
- 原附件保留；新选附件追加。编辑保存使用 PATCH，状态继续通过专用状态接口修改。
- 可选的备注、邮箱、电话、交期可明确清空；未传字段保留。记录 ID、创建者、创建时间不得被修改。

### 模型

- 详情页增加“编辑模型”，回填名称、描述、来源并调用 modelsAPI.update。
- 保留现有文件和图片，不因基础资料编辑将附件数组重置为空。模型文件与图片继续使用现有详情页上传入口，避免资料保存与附件上传的部分成功混淆。
- 服务端保留现有必填验证、审计以及索引更新逻辑。

### 耗材

- 详情页增加“编辑耗材”，回填材质、品牌、直径、颜色、单价、单位和备注。
- 非预置材质通过自定义材质回填；保留密度等表单未呈现字段。
- 对已有批次的耗材，规格变更仍遵循当前库存单位规则；此次不改变历史批次余额或过去订单描述。
- 显式空备注保存为空；缺省字段不覆盖旧值。金额、直径拒绝非有限值和部分数字解析。

### 库存批次

- 耗材详情的批次行以及库存列表提供编辑入口，打开专用批次编辑页。
- 可编辑批次号、序列号、库位、备注；沿用现有停用与启用能力。
- 所属耗材、库存数量、库存状态只读。数量更正通过原入库、出库、盘点动作形成流水，盘点仍限 Owner。
- 保存调用 stockAPI.updateLot，携带加载时的 version 并使用 useInventoryCommand 的幂等机制。
- 版本冲突显示明确提示，允许重新加载最新资料；保留用户输入供核对，不静默覆盖。请求结果未知时按既有规则复用原请求重试。

### 用户及其他表单

- 用户管理已有角色、启停、密码重置功能；补充 Staff/Viewer 姓名编辑，仍仅 Owner 管理。Owner 账号沿用受保护规则。
- 登录、初始化、导入、库存过账是业务动作，不增加任意编辑历史记录的接口。
- 入出库与盘点的已过账流水保持不可直接改写。后续完整 ERP 如需撤销单据，应单独设计冲销，保留原操作与原因。

## 4. 权限、刷新和异常

- Owner/Staff 可编辑订单、模型、耗材和批次；Viewer 无编辑入口，服务端继续拒绝写入。
- 编辑页未加载完成、加载失败或正在提交时不能保存。明确显示失败并保留表单输入；连续点击不能发送多个保存请求。
- 保存成功回到原详情，详情获得焦点后读取最新记录；列表已有焦点刷新机制继续使用。取消返回不写入数据。
- Web 成功跳转不依赖原生 Alert 的按钮回调；手机保留明确反馈。记录被删除时提示不存在。
- 审计保存修改前后值。此次不引入数据库迁移，不改 API/schema 版本；保存操作沿用当前 PATCH 契约。

## 6. 验收

1. 订单创建后编辑客户与两条明细，原 ID、状态和附件保留；单价、数量、小计、合计正确；清空备注和交期后重新打开仍为空。
2. 模型修改资料后原文件与图片可访问；失败时不出现“修改成功”。
3. 耗材编辑自定义材质、备注和单价，保存后详情和列表同步；未编辑的密度等字段保留。
4. 库存批次资料编辑不改变余额、不新增库存流水；携带旧版本的保存被拒绝；重复请求不会重复操作。
5. Viewer 请求 PATCH 被拒绝；Staff 不能盘点或修改用户；Owner 可以修改普通用户姓名。
6. 新建模式仍正常；手机与 Web 保存返回行为可用；取消不修改数据。
