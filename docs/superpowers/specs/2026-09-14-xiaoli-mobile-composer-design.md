# 小鲤移动端输入区键盘避让与长文本滚动设计

## 背景

小鲤聊天页在手机端唤起虚拟键盘后，输入区可能被键盘遮挡，用户无法实时查看正在输入的内容。输入大量文字时，输入框虽然已有最大高度限制，但没有明确的内部滚动行为，无法提供类似微信的长文本编辑体验。

## 目标

- iOS 和 Android 的虚拟键盘升起后，输入区始终保持在键盘上方。
- 输入框从单行开始随内容自然增高。
- 输入框以 5 行作为高度上限；超过可见范围后高度不再增加，改为在输入框内部上下滑动。
- 编辑长文本时，光标和当前输入位置保持可见。
- 消息列表、图片附件和发送逻辑维持现有行为。

## 非目标

- 不调整小鲤的消息气泡、空状态、图片选择或发送流程。
- 不改变聊天记录的自动滚动规则。
- 不引入新的第三方键盘或输入框依赖。

## 方案

### 页面键盘避让

继续使用聊天页现有的 `KeyboardAvoidingView`，但为两个移动平台明确配置行为：

- iOS 使用 `padding`，保留导航标题栏所需的垂直偏移。
- Android 使用 `height`，让聊天页的可用高度随软键盘缩小，使底部输入区位于键盘上方。

Android 原生配置已经使用 `adjustResize`，页面级高度避让与其配合，不修改应用级窗口策略。

### 输入框增长与滚动

输入框保持多行模式，使用字体大小、行高和上下内边距计算 5 行所需的最大高度：

- 空内容或短内容时保持现有的最小高度。
- 内容增加时由原生多行输入框自然增长。
- 达到 5 行后由最大高度截断增长。
- iOS 显式启用输入框自身的垂直滚动；Android 由多行 `TextInput` 提供原生内部滚动。
- Android 使用顶部文本对齐并关闭额外字体内边距，避免默认字号的五行预算被平台字体 padding 挤压。

消息列表和输入框是同级组件，各自处理自己的滑动手势，不需要 Android 嵌套滚动属性。输入框未达到最大高度时，页面外观不额外占用空间；达到上限后，用户在输入框内上下滑动查看全部内容。

保留 React Native 默认的字体缩放行为以支持系统无障碍字号。“5 行”是最大高度预算而不是强制可见行数；用户启用系统大字体后，实际可见内容可能少于 5 行，但仍可在输入框内部滚动查看和编辑全部文本。

### 平台与边界行为

- 发送按钮继续与输入框底部对齐。
- 键盘收起后，聊天页恢复完整高度。
- 发送成功清空内容后，输入框恢复最小高度。
- 输入框禁用期间仍保持当前高度与内容，避免图片准备或消息发送失败时草稿丢失。
- 现有图片附件区域仍位于消息列表和文字输入栏之间，并随输入栏一起处于键盘上方。

## 验证

将五行排版和平台键盘避让规则提取为可直接加载的纯策略模块；测试通过公共接口验证以下值和行为不会回归：

- 5 行、20 行高、16 垂直内边距及计算所得的 116 最大高度。
- iOS 使用 `padding` 和 88 偏移，Android 使用 `height` 和 0 偏移，Web 和未知平台使用无行为、0 偏移的中性策略。

同时保留范围精确的界面接线契约，确认真实输入框启用多行、内部滚动和顶部对齐，未使用 React Native 0.81 不支持的 `nestedScrollEnabled`；范围受限的输入样式契约确认最大高度、行高、垂直内边距均消费共享策略，并关闭 Android 额外字体内边距。

同时运行现有的小鲤聊天契约测试，确认图片附件、图片消息和发送条件保持不变。条件允许时，再在 Android 和 iOS 模拟器或真机上手动验证键盘升降、连续输入超过 5 行、输入框内部滑动和发送后复位。

## 完成标准

在 iOS 和 Android 手机上打开小鲤并聚焦输入框时，输入区不被软键盘遮挡；连续输入超过可见范围后，输入框不超过五行高度预算，并可在内部顺畅上下滑动查看和编辑全部内容。系统大字体下允许可见行数少于 5 行。
