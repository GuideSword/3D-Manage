# Agent 分层记忆与会话图片召回设计

## 背景

当前 Orchestrator 在每一轮请求中读取会话全部消息并原样发送给大模型。对话越长，请求 token、延迟和费用持续增长；如果消息内容包含图片 data URL，SQLite 体积和后续请求体还会急剧膨胀。

本设计采用轻量 Letta 式分层记忆：少量核心记忆始终可见、近期消息保留原文、较早对话滚动压缩，历史内容按需检索。向量检索只是可选增强，因此没有 Embedding 配置时，基础记忆与压缩仍能工作。

## 依赖与实施顺序

本阶段在“Agent 多图发送与独立 AI 服务配置”完成后实施。前一阶段保证图片不会以 Base64 写入消息数据库；本阶段增加服务端会话附件存储、历史图片召回和长对话压缩。

不引入 Letta 服务或 Letta SDK。项目只实现当前产品所需的分层、压缩和检索行为，继续使用现有 Express、SQLite 与用户配置的大模型。

## 目标

- 原始聊天记录继续完整保存并可供界面查看，但每轮模型调用不再携带全部历史。
- 保留最近 10 轮完整对话，并把更早内容压缩成可更新的结构化摘要。
- 保存少量受控核心记忆，避免 Agent 任意改写无限制自由文本。
- 历史图片以受保护的会话附件保存；上下文使用描述和附件 ID，不重复携带 Base64。
- 配置 Embedding 时使用向量检索旧摘要和重要记忆；未配置时使用 SQLite 全文检索。
- 压缩或检索失败不能阻断普通聊天，也不能删除原始数据。

## 非目标

- 不实现通用自主 Agent 操作系统、自主睡眠 Agent 或多 Agent 共享记忆。
- 不让模型直接删除原始消息、附件或审计记录。
- 不把订单、模型和库存业务数据复制进长期记忆；这些数据继续通过现有工具实时查询。
- 不为聊天原始消息生成逐条向量；只索引压缩摘要和经过筛选的核心记忆。

## 四层记忆

### 1. 核心记忆

核心记忆是每轮都进入上下文的短小结构，按当前用户隔离，字段固定为：

- `user_preferences`：用户明确表达的交互和输出偏好。
- `business_constraints`：用户明确说明且跨会话稳定的业务限制。
- `active_goals`：当前仍有效的长期目标。

模型不能提交任意 SQL 或覆盖整块内容。每轮完成后，受控提取器只从用户明确陈述中生成增补、替换或删除候选，并保存来源消息 ID。候选必须符合固定 JSON Schema；不符合、来源不存在或只是模型推测的内容被丢弃。每类记忆有字符上限，合计最多 4,000 个字符。

### 2. 近期上下文

模型请求保留最近 10 轮用户与助手交互及这些轮次关联的工具调用结果。系统消息、核心记忆和当前用户输入不计入 10 轮限制。较大的工具结果在进入上下文前按字段白名单裁剪，但数据库中的原始工具消息不修改。

图片在首次发送轮次以真实多模态内容进入模型。之后的近期上下文只包含附件 ID、文件元数据和首次分析得到的简短描述，不重复注入图片数据。

### 3. 滚动摘要

每个会话只有一个当前摘要，结构固定为：

- 会话目标
- 已确认事实
- 已作决定
- 未完成事项
- 重要工具结果
- 图片描述与附件引用

当即将发送的估算输入超过 12,000 token，或未压缩历史超过 10 轮时，系统把最旧且不属于近期窗口的内容合并进摘要。估算器按中文字符每字 1 token、其他文本每 4 字符 1 token 计算，并为工具 JSON 和消息包装增加 20% 余量。摘要最多 6,000 个字符。

摘要生成使用当前用户的大模型配置和严格 JSON Schema。新摘要成功写入后，记录 `summarized_through_sequence`；原始消息只标记为不再默认进入上下文，不被删除。压缩任务幂等，重复运行不会跨过相同序列或重复合并。

### 4. 归档检索

旧摘要被切分为带会话 ID、时间范围、主题和来源序列范围的归档片段。当前用户配置 Embedding 时，为这些片段和核心记忆生成向量，并按用户及配置指纹隔离；每轮根据当前问题检索最多 5 条相关片段。

未配置 Embedding 时，使用 SQLite FTS5 对相同归档文本进行全文检索。运行环境缺少 FTS5 时自动使用标准化关键词 `LIKE` 查询，基础记忆不因此失效。检索结果作为“可能相关的历史记忆”进入上下文，并包含来源范围，不能覆盖实时工具查询结果。

## 会话图片附件

客户端仍以经过限制的 data URL 提交当前轮图片。服务端验证后立即解码为二进制，写入不对外公开的 Agent 会话附件目录。文件名使用随机 UUID，扩展名由服务端识别出的 MIME 决定；客户端文件名只作为显示元数据，不能参与磁盘路径。

数据库保存附件 ID、用户 ID、会话 ID、消息 ID、MIME、字节数、内容哈希、相对存储名、创建时间、首次模型描述和状态。任何接口都不能接受客户端提供的任意附件磁盘路径。下载或查看附件必须通过认证路由，并验证附件属于当前用户的会话。

首次请求完成后，消息内容中的 data URL 被替换为附件引用。后续上下文默认只使用描述。如果用户明确要求重新查看此前图片，Agent 可调用受限的会话图片召回工具；该工具只能返回当前用户、当前会话中的指定附件，并在本轮临时重新注入图片。工具不能列举或读取其他用户附件。

删除会话时，在同一业务操作中删除附件数据库记录并安排删除对应磁盘文件。文件删除失败进入可重试清理队列；数据库备份与恢复文档需要把 Agent 附件目录纳入范围。

## 上下文组装顺序

每次模型调用按以下顺序组装：

1. 系统提示与安全规则。
2. 当前用户的核心记忆。
3. 当前会话滚动摘要。
4. 与本轮问题相关的最多 5 条归档记忆。
5. 最近 10 轮原始上下文及裁剪后的工具结果。
6. 当前用户消息和本轮新图片。

如果估算后仍超过 12,000 token，先减少归档结果，再裁剪最旧的近期轮次，但至少保留最近 3 轮和当前消息。核心记忆与系统安全规则不被裁剪。

## 数据模型

新增或扩展以下 SQLite 结构：

- `conversation_summaries`：会话 ID、用户 ID、结构化摘要、摘要版本、已覆盖序列、状态、错误摘要和更新时间。
- `core_memories`：用户 ID、类别、内容、来源消息 ID、状态和更新时间。
- `archival_passages`：用户 ID、会话 ID、文本、主题、来源起止序列、时间范围和创建时间。
- `archival_embeddings`：归档片段 ID、用户 ID、配置指纹、向量、维度和更新时间。
- `message_attachments`：附件归属、元数据、安全存储名、哈希、描述和状态。

现有 `messages` 增加稳定递增的会话内序列号和上下文状态。所有新表使用用户 ID 与会话 ID 联合约束，防止只凭附件或记忆 ID 跨用户读取。

## 失败与恢复

- 摘要生成失败：保留原始消息和旧摘要，本轮退化为系统提示、核心记忆与最近 10 轮，不阻断聊天；下次达到条件时重试。
- 摘要 JSON 不符合 Schema：拒绝写入，不用自由文本覆盖有效摘要。
- 核心记忆提取失败：跳过本轮更新，不影响回复。
- 向量检索不可用：改用 FTS5；FTS5 不可用时改用关键词查询。
- 附件写盘失败：当前图片消息不进入模型，客户端收到可重试错误并保留草稿。
- 附件缺失或损坏：上下文继续使用已有文字描述，召回工具返回明确的“附件不可用”。
- 删除清理失败：记录清理任务并重试，不把任意路径交给清理器。

## 隐私与安全

原始对话、摘要、核心记忆、归档片段和附件只允许所属用户访问。日志不记录用户原文、摘要全文、附件内容、Base64 或模型 API Key。错误和审计只记录资源 ID、大小、状态、耗时和错误类别。

附件目录不由 Express 静态托管。相对存储名解析后必须仍位于明确配置的 Agent 附件根目录内。备份、恢复和会话删除均按附件 ID 处理，不能使用客户端文件名或未验证路径。

## 验证

使用可预测的模拟 LLM 测试摘要合并和核心记忆候选。测试覆盖：

- 10 轮窗口边界、token 预算和至少保留 3 轮的降级规则。
- 摘要成功、失败、Schema 无效、重复执行和进程中断续跑。
- 原始消息始终保留，压缩只改变上下文选择状态。
- 核心记忆只接受允许类别、有效来源和明确陈述。
- Embedding 检索、FTS5 降级及关键词最终降级返回一致的归档结构。
- 不同用户和不同会话之间无法读取记忆或附件。
- 当前轮图片只写盘一次，SQLite 不含 Base64，后续普通轮次不重复携带图片。
- 显式图片召回只能读取当前会话附件。
- 删除会话会清理附件；模拟文件删除失败时进入安全重试队列。

集成测试记录长对话压缩前后的模型输入体积，确认超过 20 轮后输入不会随完整历史线性增长，并验证用户仍能从摘要或归档检索回答早期已确认事实。最后运行后端验证、Agent 数据库校验、客户端会话加载验证和备份恢复演练。

## 完成标准

- 超过 20 轮的会话不再把全部历史发送给模型，输入稳定受 12,000 token 预算约束。
- 原始聊天记录完整可查看，压缩或检索失败不会造成数据丢失或阻断聊天。
- 未配置 Embedding 时，分层记忆、摘要和全文检索仍可用。
- 配置 Embedding 后，旧摘要和核心记忆可以按语义召回，且不会混用其他用户或向量配置。
- 图片 Base64 不进入持久消息；后续引用使用描述，明确需要时才安全召回原图。
