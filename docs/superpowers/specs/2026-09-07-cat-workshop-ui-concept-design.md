# 猫爪工坊 UI 概念设计

## 背景

3D-Manage 是一款基于 React Native 和 Expo 的 3D 打印运营管理 APP，核心页面包括首页、订单、模型、耗材、设置与 AI 助手。现有界面偏专业后台，本轮只进行 UI 概念重绘，供后续决定是否进入二次开发。

## 设计目标

- 让 APP 更年轻、更符合 Z 世代审美，并形成可识别的二次元品牌气质。
- 采用“中度二次元”的软糯猫娘风格，兼顾亲和力和业务效率。
- 手机端优先，同时保留 React Native Web 的响应式实现可能。
- 支持日间与夜间护眼主题，但不维护两套页面结构。

## 已确认方向

主题名称为“猫爪工坊”。整体像一间温暖、忙碌但井然有序的 3D 打印小工坊。原创猫娘角色“小麦”承担陪伴、提醒、空状态与 AI 助手反馈；订单、库存和模型数据仍是页面主体。

正式业务名称保持不变，包括“订单”“模型”“耗材”“库存”“设置”等。工坊感只体现在视觉、问候和辅助文案中，不改写业务概念。

## 视觉系统

### 日间主题：奶油暖光

- 页面背景：奶油白 `#FFFAF4`
- 主色：蜜桃粉 `#D98A78`
- 进行中：香芋紫 `#9A7EB9`
- 完成与健康：鼠尾草绿 `#78A28D`
- 正文：可可棕 `#4C403B`
- 卡片使用暖白表面、柔和描边和低透明度暖色阴影。

### 夜间主题：可可月光

- 页面背景使用低亮度可可紫灰，不使用纯黑。
- 卡片使用略亮于背景的紫灰表面，边框保持低对比度。
- 蜜桃、香芋、鼠尾草状态色降低饱和度和亮度，保证夜间辨识但避免刺眼。
- 插画和装饰同步降低饱和度，问候语切换为夜间版本。

日夜主题共用相同布局、字号、组件和操作路径，只切换颜色、阴影、插画光照与问候文案。默认跟随系统主题，设置中提供“跟随系统 / 日间 / 夜间”三档手动覆盖。

## 角色使用规则

- 角色视觉面积不超过单屏的 15%。
- 完整角色主要用于首页提醒、AI 助手、空状态和成功反馈。
- 普通订单与库存列表不出现角色，避免影响扫描效率。
- 不使用幼态化、擦边或高暴露表达；角色定位为原创工坊助手。
- 轻动效包括点击回弹、猫耳轻晃与完成撒花，单次 150–300ms，并允许跟随系统减少动态效果。

## 页面结构

### 首页

首页依次展示问候与头像、猫娘提醒卡、待审核/执行中/低库存三张数据卡、四个快捷操作和最近订单。底部导航保持首页、订单、模型、耗材、设置五项。

### 订单

订单页采用紧凑任务流。标题和新建入口之后依次为搜索、常驻状态筛选和订单列表。订单卡突出客户、订单编号、交付日期、材料与状态，优先保证快速扫描。

### 模型

模型页采用“图鉴式浏览”。缩略图面积大于其他业务页面，支持分类筛选、列表/网格模式，并保留文件格式、文件数量和来源等元数据。

### 耗材

耗材页包含耗材与库存批次切换、汇总数据、入库/出库/盘点快捷操作和库存列表。库存风险使用柔和状态色、数量和文字共同表达，不只依赖颜色。

### 设置与 AI 助手

设置页包含账户、主题、对象存储、数据导入和 AI 服务设置。AI 助手是角色表达最完整的区域，小麦可以通过自然语言解释数据或触发现有业务操作。

### 详情、表单和交易页面

详情页沿用身份区、状态标签、分组卡片和底部操作区。新建订单、新建模型、新建耗材以及出入库页面共用表单分组、输入控件、选择器和主次按钮样式。破坏性操作与普通操作分区显示。

## 组件与状态规则

- 大卡片圆角 20–24px，小控件圆角 12–16px，胶囊标签使用全圆角。
- 页面层级固定为：标题 → 筛选工具 → 关键数据 → 业务内容。
- 蜜桃色表示待办，香芋色表示进行中，鼠尾草色表示完成或健康，柔红色表示危险。
- 加载状态保持布局尺寸稳定；空状态使用小麦插画、简短说明和主要行动按钮。
- 错误状态使用内联错误卡或系统提示，严重错误提供重试入口。
- 所有主要触控目标不小于 44px，文本和状态色满足可读性要求。

## 概念图交付

本轮生成两张手机端高保真 UI 评审图：

1. 日间“奶油暖光”核心页面总览，包括首页、订单、模型与耗材。
2. 夜间“可可月光”核心页面总览，使用相同结构验证护眼适配。

概念图用于确认视觉方向，不直接作为 APP 页面资源。进入开发后，所有页面、文字、图标和主题都应使用 React Native 组件与设计令牌实现。

## 非目标

- 本轮不修改前端代码、后端接口或业务数据结构。
- 不增加新的业务功能。
- 不将核心运营界面改成游戏化任务系统。
- 不强制按固定时段切换主题。

## 后续决策

用户评审两张高保真概念图后，再决定是否进入二次开发。若进入开发，应先制定组件、主题令牌、导航和页面迁移计划，再分阶段实施与验证。
