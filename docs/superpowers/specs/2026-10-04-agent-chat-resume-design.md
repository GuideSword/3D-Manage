# AI 聊天会话续接设计

日期：2026-10-04。对应 ERP 顺序 01A；用户已授权达到阶段 01 约 95% 后继续顺序执行。

## 范围与取舍

沿用现有 SQLite `conversations`、`messages`、最近十轮、滚动摘要和 8K token 预算。客户端每次进入助手读取当前账号最近会话，默认打开上次会话，提供历史、删除和新对话入口。完整消息仍保存在服务端；客户端只保存当前会话指针与未发送的文字草稿，按服务器和账号隔离。

考虑三种做法：只在客户端缓存消息，无法可靠覆盖换设备和服务端断线；另建“长期记忆库”，重复现有会话和摘要；复用现有服务端会话并补充中断状态，改动最小且能保留原始记录，因此采用第三种。

## 中断与重试契约

服务端接收用户消息并写入 SQLite 后，发送包含 `conversationId`、`messageId` 的 `accepted` 事件。正常完成将消息标为 `complete`。客户端断开、模型失败或流式失败时，保留用户消息及已存图片引用，清掉该轮未完成的助手/工具记录，并把用户消息标为 `interrupted`；页面展示“回复已中断”。重试必须由用户点击，携带原会话和消息 ID，服务端只允许重试该会话最后一条中断的用户消息，复用它而不另写一条。重试文字内容必须相同；含图片的中断轮次提示重新选择图片，不自动重传或执行工具。

旧客户端不传重试 ID 时保持原发送格式。带了不存在或不属于当前账号的 `conversationId`，直接拒绝，不能静默新建会话。服务端对同一账号继续使用现有并发聊天限制；业务确认动作继续由用户单独点击，不随对话恢复自动执行。

## 客户端行为

进入助手先读取会话列表，若本地指针属于当前列表则打开它，否则打开列表最新一项。请求详情只使用当前账号授权接口；切换账号/服务器后丢弃过期请求结果。新对话只清空页面会话指针，第一次发送时由服务端创建。删除当前会话后选择最新剩余会话或显示空白欢迎页。未发送的文字草稿保存在同一服务器、同一账号的本地键中；退出登录清理本地键，另一个账号即使使用同一设备也看不到草稿。图片仅在本次页面内有效，重开时提示重新选择。

## 验证与发布

先用隔离数据库验证归属、列表/详情/删除、正常完成、服务端已接收后断线、同消息重试不重复、账号切换和备份恢复。Web 与物理 Android 验证重开和继续提问。正式 Docker 发布前沿用阶段 01 的备份与隔离恢复流程；构建覆盖安装 APK 后验收，不改正式用户密码或聊天配置。
