# “小鲤”赛博猫娘首页重设计

## 背景

3D-Manage 当前首页已经具备订单概览、快捷操作、最近订单和五项底部导航。本次仅重设计首页样板，将其调整为已确认的蓝紫色赛博二次元风格；业务接口、权限模型、路由和订单状态定义保持不变。

视觉方向以用户确认的聊天内效果图为准：高明度蓝紫主视觉、原创角色“小鲤”、粉蓝双色状态卡、四项快速入口、最近订单和悬浮胶囊底栏。

## 目标

- 首页尽量还原参考图的布局密度、梦幻光效、圆润卡片和清晰信息层级。
- 将原角色“小麦”更名为“小鲤”，并将首页角色重设计为原创蓝紫色赛博猫娘。
- 使用 React Native 原生组件承载文字、数据、卡片和交互，角色插画作为独立透明图片资源。
- 同时支持蓝紫日间主题和深紫夜间主题，继续服从现有主题设置。
- 保留并重新设计“最近订单”，不改动现有业务能力。

## 非目标

- 本阶段不重设计订单、模型、耗材、设置、详情页或表单页。
- 不新增后端接口、消息系统或新的订单状态。
- 不直接复制参考图中的角色、商标或其他受保护素材。
- 不把页面文字和动态数据烘焙进整张背景图。

## 视觉系统

### 日间主题：蓝紫晴空

- 页面底色采用接近白色的冷调薰衣草色。
- 主视觉使用浅蓝到淡紫渐变，叠加低对比度 3D 打印工坊剪影、星光和柔和光晕。
- 主色使用电光紫，辅助色使用亮蓝与青色；待审核使用荧光粉，执行中使用亮青蓝。
- 卡片以半透明浅色表面、细描边和柔和蓝紫阴影表现玻璃感。
- 正文使用深靛蓝，次要文字使用低饱和蓝灰，保证业务信息可读。

### 夜间主题：深紫霓虹

- 页面底色切换为深靛紫，不使用纯黑。
- 主视觉使用深蓝紫渐变和降低亮度的工坊剪影。
- 卡片切换为半透明深紫表面，保留低强度霓虹描边和阴影。
- 粉色、青色状态色降低明度和饱和度，避免夜间刺眼。
- 页面结构、字号、触控范围和交互路径与日间主题完全一致。

## 首页结构

### 1. 顶部主视觉

顶部主视觉约占首屏上部三分之一。左上显示“小鲤”头像和“运营概览”胶囊，右上显示通知入口。左侧依次显示“欢迎回来！”和“关注订单进度，掌控生产全局”，右侧放置“小鲤”半身插画。

主视觉底部叠放两张半透明统计卡，分别展示待审核订单和执行中订单的实时数量。点击统计卡进入带对应状态筛选的订单页。

原首页导出入口不再占用顶部主视觉位置。用户仍可通过现有业务入口执行导出；本次不删除导出能力。

### 2. 核心状态卡

主视觉下方依次显示两张横向大卡：

- 待审核订单：粉色描边、待处理标签、数量、说明和前进按钮。
- 执行中订单：青蓝描边、进行中标签、数量、说明和前进按钮。

每张卡左侧使用“小鲤”的 Q 版透明插画，右侧使用低透明度业务线稿作为装饰。卡片整体可点击，进入对应状态的订单列表。加载时保持卡片尺寸稳定并使用省略占位。

### 3. 快速入口

使用四列方形入口：

- 全部订单：进入订单页。
- 生产进度：进入执行中订单列表。
- 库存风险：进入耗材页的库存批次视图。
- 消息中心：本阶段映射到现有 AI 助手入口，用于查看运营提醒，不新增独立消息后端。

快捷入口根据现有权限显示或禁用，不向无权限用户暴露可写操作。

### 4. 最近订单

保留最近订单区，展示最多四条订单。每条包含模型或订单缩略图占位、客户或订单名称、订单编号、状态和时间信息，点击进入订单详情。

列表使用紧凑的浅玻璃卡片，以状态文字和色彩共同表达进度。空状态改用“小鲤”文案；接口失败继续使用现有错误提示和下拉刷新逻辑。

### 5. 底部导航

继续保留首页、订单、模型、耗材、设置五项导航，不改变路由。视觉调整为悬浮胶囊式半透明底栏，当前项使用蓝紫渐变感背景、发光图标和高对比度标签。

## 角色“小鲤”

“小鲤”是原创成年感赛博猫娘工坊助手：银紫色头发、蓝紫色眼睛、深蓝与薰衣草色工作连帽服、霓虹猫耳耳机，性格友好、专业、活泼。

首页需要三类独立透明资源：

1. 顶部半身主视觉。
2. 待审核卡 Q 版动作。
3. 执行中卡 Q 版动作。

资源不得包含文字、背景、商标或参考图角色的特征复刻。React Native 页面负责所有文字与业务信息，插画只承担品牌和氛围表达。夜间主题可以复用相同角色资源，通过背景、遮罩或透明度控制融入效果。

## 组件边界

- `HomeHero`：背景、欢迎文案、头像、通知和顶部统计卡。
- `OrderStatusCard`：可复用的粉色/蓝色订单状态大卡。
- `QuickAccessGrid`：四项快速入口及权限处理。
- `RecentOrdersSection`：最近订单、空状态和详情跳转。
- `CyberTabBar`：五项底部导航的视觉配置。

首页容器负责加载和刷新数据；子组件只接收展示值、主题令牌和回调。组件不直接调用 API，避免视觉重构改变数据流。

## 数据与交互

继续并行读取待审核订单、执行中订单、最近订单和库存批次。接口响应转换方式、鉴权错误处理、下拉刷新和页面聚焦刷新保持现状。

核心跳转关系如下：

- 待审核统计与大卡 → 订单页，筛选“待审核”。
- 执行中统计与大卡 → 订单页，筛选“执行中”。
- 全部订单 → 订单页。
- 生产进度 → 订单页，筛选“执行中”。
- 库存风险 → 耗材页，打开库存视图。
- 消息中心 → 现有 AI 助手入口。
- 最近订单行 → 对应订单详情。

## 响应式与可访问性

- 手机端为主要目标，适配窄屏 Android、iPhone 安全区和 React Native Web。
- 主视觉人物允许在窄屏裁切，但欢迎语、统计数值和主要操作不得被遮挡。
- 所有主要触控目标不小于 44px。
- 状态不能只靠颜色表达，必须同时显示文字或图标。
- 重要文字与背景保持足够对比度；夜间主题避免高强度大面积霓虹。
- 动效仅限轻微按压、淡入和光效，不影响减少动态效果用户。

## 错误、加载与空状态

- 首次加载使用稳定尺寸的省略占位或骨架，不造成布局跳动。
- 下拉刷新继续显示主题色刷新指示器。
- 部分接口失败时尽量展示其余已加载模块；鉴权失败交由现有全局流程处理。
- 最近订单为空时显示“小鲤”空状态和新建订单提示；无写权限用户只显示说明。

## 验收标准

- 首页在日间和夜间主题下均能正常展示，主题切换不改变布局。
- 待审核、执行中和低库存数据来自现有接口，刷新与聚焦重载正常。
- 所有统计卡、快捷入口、最近订单和底部导航跳转正确。
- 原有角色名称在本次涉及的首页文案中全部替换为“小鲤”。
- 页面没有把动态文字或订单数据烘焙进图片。
- Android、iOS 和 Web 导出构建至少完成静态验证；关键数据与导航逻辑具备针对性测试或人工验证记录。
- 视觉效果与已确认样板保持一致：蓝紫主视觉、原创“小鲤”、粉蓝状态卡、四项快速入口、最近订单和悬浮底栏。
