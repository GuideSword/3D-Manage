# model-import 设计规范

## 目标

为 3D-Manage 增加一个独立 Windows 本地助手工作流，帮助用户从本机文件夹批量扫描并导入模型文件。工作流支持格式筛选、递归扫描、ZIP 安全解压、重复检测、可中断传输、断电恢复、失败后继续和导入结果追溯。

第一版复用现有 Windows 模型交接助手与 `manage3d-model://` 协议。扫描器、任务引擎和清理逻辑与界面解耦，未来可以替换为 Electron/Tauri 界面。

## 已确认的产品决策

- 第一版形态：独立 Windows 本地助手，同时支持从模型库启动和独立启动。
- 每个模型文件自动创建一个模型资产。名称取文件名（去扩展名），来源为 `imported`。
- 递归扫描所选文件夹的全部子文件夹，并记录完整源路径和相对路径。
- 支持 STL、OBJ、3MF、STEP、STP；ZIP 先在本地安全解压，再扫描其中的目标格式。
- SHA-256 已存在时自动跳过，不创建重复资产；结果必须显示文件名、完整路径、SHA-256 和跳过原因。
- 默认 2 路并发，允许设置为 1–4 路；服务端能力限制优先于本地设置。
- 单文件失败后记录失败并继续其他文件，批次结束后支持单独重试。
- 取消任务需要二次确认。确认后中断当前请求、删除当前缓存、清理 pending 模型和临时对象；成功项永久保留。
- 断电或崩溃后，下次启动先执行修复清理，再由用户选择继续未完成任务或取消任务。
- 描述采用两层：本机生成可验证的事实描述；用户开启后再请求服务端/云端 AI 生成特征和用途建议。
- 第一阶段只开放 owner/staff，AI 增强默认关闭，保留现有单模型上传和模型交接流程。

## 用户流程和界面

采用四步向导与传输工作台：

1. **选择文件夹**：使用 Windows 文件夹选择器，显示所选根目录。
2. **选择格式**：滑动列表或多选列表展示 STL、OBJ、3MF、STEP/STP、ZIP；显示 ZIP 会先解压扫描。
3. **扫描预览**：显示目标文件总数、重复数、格式错误数、预计总大小；列表显示文件名、完整源路径、相对路径、格式、大小、SHA-256 和预期动作。
4. **正在导入**：显示四步进度、已完成/剩余/跳过/失败统计、当前文件进度、并发数、失败列表和重试入口。

传输工作台包含：

- 左侧工作区导航：概览、批量导入、历史任务、设置。
- 顶部连接状态和已绑定服务器信息。
- 任务队列表格，区分传输中、已完成、已跳过和失败。
- 当前传输卡片，显示文件名、大小、上传模型 ID、进度和预计剩余时间。
- 取消任务按钮。确认弹窗必须明确说明：当前文件会中断、缓存和空记录会清理、成功项会保留。
- 设置卡片：选中格式、ZIP 解压开关、事实描述、AI 增强、并发数、失败后继续、断电恢复。

## 架构和数据流

### 网页/RN 控制面

模型库新增“批量导入”入口。网页负责授权和启动本地助手，不直接访问用户本机目录。通过现有 `manage3d-model://` 协议传递已绑定服务器地址和一次性短期票据；独立启动时使用助手本地保存的服务器绑定配置。

### Windows 数据面

助手负责：

- 文件夹选择和递归枚举。
- 扩展名筛选和 ZIP 安全解压。
- SHA-256 和可验证文件事实信息计算。
- 任务 manifest 原子持久化。
- 1–4 路并发上传和可取消 HTTP 请求。
- 失败重试、断电恢复和清理。
- 可选的描述增强请求。

实现上扩展 `tools/model-handoff`，新增导入专用入口和核心模块；不改变现有 Bambu Studio 交接行为。

### 本地任务持久化

每个批次保存到：

```text
%LOCALAPPDATA%/3DManageModelHandoff/imports/<jobId>/
```

目录至少包含：

- `manifest.json`：任务、选项和逐项状态。
- `manifest.json.tmp`：写入中的临时文件，成功后原子替换。
- `errors.jsonl`：可追加的错误记录，禁止写入票据和传输令牌。
- `cache/`：仅保存当前传输需要的解压或处理缓存。

每个条目保存 `jobId、itemId、relativePath、originalName、extension、size、sha256、modelId、state、descriptionFacts、descriptionAi、errorCode、createdAt、updatedAt`。

### 服务器数据面

新增 `backend/routes/modelImport.js`，通过幂等的 `jobId + itemId + sha256` 处理批量导入。模型记录在文件完整校验前保持 `pending`，只有文件写入、大小校验和 SHA-256 校验全部通过后才变成 `completed`。

## 状态模型

任务级状态：

```text
draft → scanning → ready → running → cancelling → cancelled
                                      └──────────→ completed
                                      └──────────→ completed_with_errors
```

发现上一次任务停在 `running`、`uploading` 或 `verifying` 时，进入 `recovery_required`，完成服务器和本地清理后再让用户选择继续或取消。

单文件状态：

```text
discovered → queued → preparing → uploading → verifying → completed
     ├──────────────→ duplicate
     ├──────────────→ failed
     └──────────────→ cancelled → cleaned
```

取消顺序：停止派发新文件、将任务置为 `cancelling`、取消活动请求、删除本地临时文件、调用服务器清理接口、保留 completed 项，最后置为 `cancelled`。服务器清理必须可重复调用。

## 后端接口

### `POST /model-import/jobs`

创建批次，保存客户端 `jobId`、格式列表、递归选项、并发设置和描述选项。返回服务器任务 ID、最大并发数和允许的扩展名。

### `POST /model-import/jobs/:jobId/items/prepare`

提交单文件元数据。服务器验证扩展名、大小和 SHA-256；发现相同 SHA-256 时返回 `duplicate` 以及已有模型的文件名和路径。否则创建带 `pending` 标记的模型占位记录，模型名称取去扩展名后的文件名，事实描述写入 `descriptionFacts`。

### `POST /model-import/jobs/:jobId/items/:itemId/file`

接收 multipart 文件，复用现有模型存储和预览生成逻辑。服务端完成大小和 SHA-256 校验后，将文件和模型标记为 `completed`。校验失败时保持 pending，返回稳定错误码。

### `GET /model-import/jobs/:jobId`

返回服务器批次和每个条目的状态，用于断电恢复对账。服务器完成的条目优先于本地 manifest。

### `POST /model-import/jobs/:jobId/cleanup`

幂等删除本批次 pending 模型、未完成对象和临时任务记录；completed 项不可被该接口删除。

### `POST /model-import/jobs/:jobId/items/:itemId/describe`

可选生成 AI 描述。默认只使用服务器已有元数据和预览图；选择云端 AI 时须在助手中明确提示，并只发送必要的预览/元数据。AI 结果单独写入 `descriptionAi`，包含来源、生成时间和模型版本。

### `DELETE /model-import/jobs/:jobId`

取消批次并调用同一套 cleanup 逻辑，不删除 completed 项。

## 安全和异常处理

- 助手只接受已绑定 HTTPS 服务器和一次性短期票据；不记录票据、传输令牌或原始文件内容。
- ZIP 解压阻止路径穿越、符号链接、超过文件数量限制、超过解压总大小限制和异常压缩比。
- 客户端和服务端都校验扩展名、大小和 SHA-256。
- 所有接口要求 `owner/staff` 角色；服务端拒绝跨用户或跨任务的 item 操作。
- 本地缓存按 job 隔离，成功确认或取消清理后删除；源文件永不覆盖。
- HTTP 失败按错误类型区分：网络错误指数退避重试；认证/权限错误立即停止该项并提示重新授权；格式或校验错误直接失败；服务器容量错误等待后重试。
- 单项失败不会改变其他条目；任务完成后若仍有失败项，状态为 `completed_with_errors`。

## 描述生成

事实描述由本机立即生成，至少包含文件名、相对路径、格式、大小和 SHA-256。解析器能够可靠得到几何统计时增加顶点数、面数或包内文件数；无法确认的数据不写入事实描述。

AI 描述是可选增强，不阻塞文件完成状态。服务端优先使用模型预览和元数据生成用途/特征建议，并保存来源和版本。默认展示事实描述；用户开启增强后才把 AI 建议作为模型描述候选，事实字段永远保留。

## 测试和发布

### 自动化测试

- 扫描器：递归目录、扩展名、中文路径、ZIP 路径穿越、符号链接、压缩限制、SHA-256、重复检测和事实描述。
- 任务引擎：manifest 原子写入、状态转换、1–4 路并发、失败后继续、取消中断、重试幂等和模拟写入中断恢复。
- 后端：重复 SHA-256、幂等 prepare、hash/size 不一致、只清理 pending、completed 保护、权限和并发上限。
- 端到端：5 个模型在第 3 个传输时取消；网络断开；进程强制结束；电脑重启；ZIP 混合格式；重复文件和中文文件名。

### 分阶段发布

第一阶段仅 owner/staff 可见，默认 2 路并发和事实描述，AI 关闭。第二阶段根据失败率和资源占用开放 AI 增强、1–4 路并发和批次历史。发布前验证 Windows 安装包、协议注册、HTTPS 绑定、服务器清理、旧版助手兼容性和成功模型不被误删。
