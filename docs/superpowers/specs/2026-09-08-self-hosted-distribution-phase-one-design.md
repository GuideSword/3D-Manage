# 自托管整包交付第一阶段设计

> 2026-09-08 计划审查修订：产品方向已确认；下文的实现约束与交付建议尚需代码、容器和设备验收，不能视为已完成功能。

## 目标

把当前开发环境项目推进为可以交付给单个组织的自托管产品：客户下载前端安装包，在自己的服务器部署后端，首次打开客户端时填写服务器地址，初始化组织 Owner，随后所有正式业务数据只保存在该组织的后端。

## 产品边界

- 每套后端只服务一个组织，不在第一阶段实现多租户。
- 一个客户端同一时间只连接一个后端。更换后端必须退出当前账号并重新登录。
- 订单、模型、耗材、库存、审计、AI 对话和正式文件均以服务端数据为准。
- 客户端只保存服务器配置、主题和登录令牌；退出时删除账号令牌、内存数据、草稿和临时文件。
- 第一阶段不提供离线业务数据缓存。
- 官方托管 Viewer 模式保留为后续能力，本阶段只实现客户自托管模式。
- 第一阶段建议验收 Android 独立安装包与 Linux x86_64 单实例后端；iOS、商店上架、ARM64 和 Windows Server 原生容器另行验证。Docker Compose/PostgreSQL 是实施方案，不是已经完成的交付能力。

## 客户端启动状态

客户端启动时依次判断：

1. 读取设备中保存的服务器配置。
2. 未配置时进入服务器设置页。
3. 已配置时请求服务端公开信息接口。
4. 服务端不可达或版本不兼容时进入连接故障页，允许重试或更换服务器。
5. 服务端尚未初始化时进入组织与 Owner 初始化页。
6. 服务端已初始化且本地令牌有效时进入主界面。
7. 服务端已初始化但令牌缺失或失效时进入登录页。

服务器地址接受 IP 或域名以及可选端口（1–65535），IPv6 使用括号形式。规范化为包含协议和 `/api` 的基础地址；首版只支持根路径或 `/api`，拒绝任意代理子路径、URL 内账号密码、查询参数和片段。无协议域名默认 HTTPS，局域网 IP 可显式确认 HTTP。手机 localhost 指手机本身；正式安装包不静默连接 localhost。证书错误通过受信任证书解决，不关闭校验。

## 服务端身份与兼容协议

后端提供公开的 `GET /api/system/info`，返回产品标识、不可变 `serverId`、组织名称、初始化状态、API 版本、服务端版本和能力列表。客户端通过产品标识防止连接到错误服务，通过 `serverId` 隔离本地会话，通过 API 版本判断兼容性。

`POST /api/system/bootstrap` 只在用户集合为空且系统未初始化时可调用，且必须提供由部署方配置的高熵 `BOOTSTRAP_TOKEN`（X-Bootstrap-Token 请求头），避免被访问者抢先创建管理员。口令不写入客户端长期存储、审计或日志。接口在同一个存储事务中写入组织信息、第一个 Owner 和审计记录；并发请求只能一个成功。初始化成功后入口永久关闭；响应丢失时重新探测状态并登录，不再次创建。

serverId 在首次持久化初始化中生成，读接口不能生成或更换它。旧数据通过版本化迁移补齐 system 与 tokenVersion，有 Owner 的旧实例标记已初始化；没有有效 Owner 的异常数据进入主机恢复流程，不开放公共初始化。未知的新 schema 拒绝启动。相同 IP/域名返回不同 serverId 时，客户端强制退出并显示服务器变化。

后续账号由 Owner 创建。公开注册入口从客户端移除，后端不再允许匿名注册 Staff 或 Viewer。

账号密码重置、角色变更、停用会提升 tokenVersion，所有受保护入口（包括 `/auth/me`）统一校验；重新启用不会复活旧 token。提供本人改密码及主机控制台 Owner 恢复，禁止匿名恢复或自动提权。

## 会话与本地数据

服务器配置使用设备级存储；Native 令牌使用 SecureStore，Web 验证端采用标签页 sessionStorage，不宣称 Web 具有 Native 安全存储能力。凭证隔离键 serverKey 来自“规范化 API 地址 + serverId”，不能只信任对方声称的 serverId。

更换服务器先匿名探测候选地址，探测失败不更改旧配置及会话。探测成功后冻结旧动作、提升 sessionEpoch、取消 API/SSE/文件操作、清空用户及导航状态，删除旧/候选残留令牌和 App 临时文件，最后保存并启用新配置。持久化或清理失败时保持退出状态、保留旧地址并可重试；不能恢复旧登录。旧请求的成功、401、登录 token 保存等回调均不得影响新 epoch。取消客户端请求不代表服务端写入回滚，写请求超时不自动重试。

退出登录清理本机凭证，不等于撤销被复制到其他设备的 stateless JWT；tokenVersion 变更提供服务端失效机制。切换时不把旧 JWT 发给候选服务器、外部文件 URL 或对象存储签名地址。

客户端不持久化业务列表和详情。登记 App 自己创建的上传/预览/下载临时文件，在退出、切换及异常后重启时清理；不能删除用户源文件。用户明确导出到外部目录的副本不随退出删除。API 和私密文件 no-store，Web blob URL 及时释放；系统及浏览器控制的缓存、截图和用户副本不能承诺安全擦除。Android 文件下载需补原生实现，当前 Web-only helper 不满足交付。

## 权限和敏感配置

所有业务写接口继续由后端授权。AI 草稿确认必须要求 Owner 或 Staff，AI 工具执行继承当前用户身份。审计操作人只从 JWT 中取得。

OSS、JWT、数据库和服务端 AI 公共密钥属于部署配置，不在移动端保存。客户端不向签名接口提交 OSS Secret。后端从环境变量读取存储配置，只返回短时、限定对象键和方法的预签名 URL。

默认保护预览图片及附件，不因图片扩展名匿名放行。OSS 上传键由后端分配，完成上传与业务对象关联，禁止任意签名覆盖现有对象。AI 用户自带 Key 可继续提交后端加密保存；客户启用外部 AI 时，选定的对话和业务数据会发送给其配置的提供方，自托管不意味着所有处理都没有外部服务。

## 部署形态

建议标准交付使用 Docker Compose：应用容器连接 PostgreSQL，业务文件和 AI SQLite 数据放入持久化卷。第一阶段保留 JSON 文档存储抽象，以 PostgreSQL 带事务锁的 JSONB 行保存业务数据；关系表重构另行实施，但须提供现有 store.json 的只读检查、停写迁移、空目标限制和核验工具。默认采用后端本地文件卷，OSS 是可选配置并单独验收。

生产部署必须提供独立随机 JWT/AI 加密密钥、初始化口令、存储配置与 Web 访问来源（没有 Web 客户端可为空允许列表）。Owner 姓名密码通过受口令保护的初始化流程输入，不放入公开配置模板。缺失或使用 CHANGE_ME_ 值时拒绝启动；等待迁移与存储检查成功才监听。支持 Linux 非 root 用户的挂载写权限，并提供受信任 HTTPS 代理配置。单实例部署 AI SQLite，不承诺水平扩容。

交付包包含 Linux/PowerShell 备份恢复脚本、调度说明、持久化目录、版本 manifest 和升级回退流程。采用短暂停写的冷备份，一致保存 PostgreSQL dump、AI SQLite 整个目录和上传文件。独立保管解密密钥/部署配置；新主机恢复也必须可用。恢复先校验格式/hash/版本及目标身份，在隔离库和目录试恢复，通过后切换；保留旧数据，失败不可启动混合状态。使用 OSS 时另行备份远端对象，不能声称本地文件归档包含它们。

Android 交付是可直接安装的签名 APK，AAB 仅用于商店通道。沿用现有 package ID 直到确认发布归属，保证后续升级签名连续。EAS 凭证、域名证书、Docker 与真机属于需要记录的验证前提；缺少时列为未验证，不能提前宣称发布完成。

## 验收标准

- 全新安装的客户端可以配置服务器、测试连接并保存配置。
- 全新后端只能成功初始化一次，第一个账号固定为 Owner。
- 客户端重新启动后仍连接同一服务器，但退出后不保留登录状态和业务草稿。
- 更换服务器不会携带上一服务器的令牌或业务状态。
- Viewer 不能通过普通 API 或 AI 入口创建或修改业务数据。
- 客户端和请求体中不出现 OSS Secret、JWT Secret 或数据库凭证。
- Docker Compose 在空目录中能够启动，通过健康检查，并在重启后保留数据与文件。
- 备份恢复演练可以恢复登录、订单和已上传文件。
- Android 安装包可以安装并连接到测试部署。
- 并发初始化防抢占、旧 schema 迁移、两服务器延迟响应/401、账号停用及密码重置都通过自动化验证。
- Linux 干净部署、文件卷权限、旧文件数据迁入 PostgreSQL、故障回滚和空机恢复均有实际记录。
- 退出后没有旧页面、AI SSE 和 App 临时文件残留，外部 URL 未收到 JWT；Android 鉴权下载可用。
- 关闭 Metro 后独立 APK 完成初始化、登录、上传下载、LAN/HTTPS 和版本覆盖安装测试，发布 manifest 记录真实产物校验值。

## 非目标

- 多租户和一个后端服务多个组织。
- 多服务器账号快速切换。
- 离线业务编辑与同步。
- 关系型业务表全面重构。
- SSO、MFA、审批流和官方托管 Viewer 模式。
- 自动应用更新和商业授权激活。
