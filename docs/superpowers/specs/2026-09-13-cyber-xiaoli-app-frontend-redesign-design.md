# “小鲤”APP 级前端视觉重构设计

## 背景

首页已完成蓝紫色赛博二次元风格改版，并建立了“小鲤”角色、日间/夜间主题、粉蓝状态色和悬浮底栏。本阶段把同一视觉语言扩展到整个 Expo / React Native APP，包括底部主页面、详情页、表单页、库存事务页、设置与用户管理、AI 助手、登录与服务器流程以及异常状态页。

本次是前端表现层重构。后端接口、权限模型、业务状态、数据语义、路由名称和既有操作结果保持不变。

## 已确认方向

- 采用“品牌点缀型”方案：业务信息优先，小鲤集中出现在首页、AI 入口、空状态、引导与成功反馈中。
- Android 手机为主要验收目标，同时保持 iOS 与 React Native Web 可用。
- 允许在不改变业务行为的前提下重新组织页面信息层级、按钮位置和辅助文案。
- 第一验收单元为“订单”和“模型”两个真实页面；确认后按同一系统扩展全 APP。
- AI 入口必须使用首页同一位“小鲤”的正式角色形象，不使用 Emoji 或脱离现有角色的抽象猫图标。

## 视觉系统

### 主题

将首页的蓝紫日间版和深紫夜间版提升为全局语义令牌。全站统一使用冷调薰衣草背景、半透明玻璃表面、蓝紫主色、粉色待处理状态和青蓝执行状态。夜间主题使用深靛紫而非纯黑，并降低大面积霓虹亮度。

主题切换只改变颜色、阴影和装饰强度，不改变信息结构、字号、触控面积或交互路径。

### 角色与品牌

首页保留大幅“小鲤”主视觉。普通业务页不放置大幅角色，避免挤压首屏业务数据；页面右上角可使用由 `assets/xiaoli/hero.png` 裁切出的角色头像作为现有 AI 助手入口，并加小型 `AI` 角标明确功能。

空状态、首次引导和完成反馈可使用现有 Q 版角色资源。角色资源只承担品牌和氛围表达，业务文字、状态和动态数据继续由 React Native 原生组件呈现。

### 页面语言

- 页面标题使用英文眉题、中文主标题和一句简短说明，延续首页的清晰层级。
- 卡片使用圆角玻璃表面、细描边和低强度蓝紫阴影。
- 状态同时使用颜色、文字和图标表达，不能只依赖颜色。
- 主要触控目标不小于 44px；窄屏优先保住主操作、关键数值和可读性。
- 列表页保持业务密度，装饰不占用独立大区块。

## 信息架构与组件边界

### 全局基础

扩展现有主题上下文，使首页和其他页面共享同一套语义颜色、渐变、边框和阴影。新增可复用的页面背景、品牌页头、AI 头像入口、玻璃卡片、状态胶囊、筛选胶囊、数据摘要卡、表单分组、反馈状态和浮动主操作组件。

展示组件只接收内容、状态和回调，不直接调用 API。页面容器继续负责数据加载、权限判断、导航和写操作。

### 页面家族

1. **核心列表页**：订单、模型、耗材。统一页头、搜索、筛选、摘要数据、列表/网格卡和悬浮主操作。
2. **详情页**：订单详情、模型详情、耗材详情。统一概览区、状态区、信息分组、关联数据和底部操作区。
3. **创建与事务页**：创建订单、创建模型、创建耗材、入库、出库、调整库存。统一步骤层级、表单分组、字段状态、校验提示和提交操作。
4. **系统与管理页**：设置、用户管理、AI 设置、数据导入。统一设置分组、说明行、危险操作和权限可见性。
5. **入口与异常页**：登录、服务器设置、所有者初始化、连接错误。使用更强的“小鲤”品牌表达，但保持错误信息和恢复操作清晰。
6. **AI 助手页**：沿用现有会话与工具调用逻辑，统一角色头像、消息气泡、输入区和确认卡的蓝紫视觉。

## 第一验收单元

### 订单中心

- 保留现有订单读取、搜索、状态筛选、下拉刷新、详情跳转、删除和长按更新状态。
- 使用紧凑品牌页头和“小鲤 AI”头像入口。
- 搜索与筛选形成一个连续控制区；增加只基于已加载数据计算的轻量摘要，不新增 API。
- 订单卡强化客户名、订单号、状态、总价、交期、创建时间和项目预览的扫描顺序。
- 删除仍服从 `canWrite`，终态订单的长按限制保持不变。

### 模型图鉴

- 保留现有模型读取、搜索、来源筛选、列表/网格切换、下拉刷新和详情跳转。
- 使用与订单一致的品牌页头、搜索区和 AI 入口。
- 模型卡突出预览图、名称、来源、文件数、图片数和更新时间。
- 保留列表与双列网格两种模式；新建入口仍服从 `canWrite`。

## 数据流与业务隔离

页面继续通过现有 API 模块获取和修改数据。视觉组件不创建新的网络请求，不改变请求参数、响应转换、鉴权错误处理或权限工具函数。

所有路由名称和参数保持兼容，包括首页通过 `status`、`tab` 与 `homeRequest` 触发的重复筛选。订单状态转换、库存增减、导入、用户管理和 AI 工具调用均保留原逻辑。

重构时优先移动 JSX 和样式；若需要抽取组件，只把纯展示或通用交互封装出去，不把业务状态机复制到新组件。

## 加载、错误与空状态

- 首次加载使用稳定尺寸的加载反馈，避免页面跳动。
- 下拉刷新继续使用当前主题主色。
- 鉴权失败继续交给现有全局登录流程处理。
- 网络或业务错误继续使用现有提示语义，不把失败误显示为空数据。
- 空状态使用“小鲤”品牌文案和现有角色资源；写入操作只向具备权限的用户显示。
- 提交中禁用重复操作，并保留现有成功、失败和确认弹窗行为。

## 响应式与可访问性

- 以约 390px 宽 Android 屏幕设计，并验证 320px 窄屏。
- Web 端限制主要内容最大宽度，避免卡片无限拉伸；宽屏可增加列数但不改变操作语义。
- 支持安全区、长内容滚动、超长名称截断和系统字体缩放下的基本可读性。
- 交互控件保留无障碍角色、标签和选中状态；状态信息同时提供文字。

## 分阶段实施

1. **视觉基础与第一验收单元**：全局令牌、通用品牌组件、订单页和模型页。
2. **库存与核心详情**：耗材列表、订单详情、模型详情、耗材详情。
3. **表单与库存事务**：所有创建页、入库、出库和调整页。
4. **系统、入口与 AI**：设置、用户、导入、AI、登录、服务器和异常页面。
5. **全站收口**：窄屏、日夜主题、权限角色、空数据、超长内容和三平台静态构建验证。

每个阶段都应产生可运行、可回归的 APP，不等待最终阶段才统一修复。

## 验证策略

- 为纯主题映射和展示辅助函数补充轻量单元验证。
- 扩展客户端冒烟测试，覆盖订单搜索/筛选/详情、模型筛选/视图切换/详情以及 AI 入口。
- 执行 `npm run verify:client`。
- 执行 Expo Android、iOS 和 Web 静态导出。
- 第一验收单元生成日间、夜间、390px 和 320px 截图，与首页并排检查视觉一致性。
- 全站完成后使用真实后端验证管理员、操作员和只读用户的入口与操作权限。

## 验收标准

- 订单和模型真实页面与已确认预览方向一致，并与当前首页属于同一视觉系统。
- AI 入口使用“小鲤”正式角色头像，功能语义清楚，不出现 Emoji 替代头像。
- 所有既有业务入口、权限、路由、状态与数据行为保持可用。
- 日间与夜间主题布局一致，390px 与 320px 手机宽度无关键内容遮挡。
- 后端目录和 API 业务逻辑没有因视觉重构发生修改。
- 用户确认第一验收单元后，可按同一设计系统扩展到整个 APP。
