# Docker 后端一键脚本交接文档设计

## 目标与位置

创建 `docs/2026-09-13_Docker后端一键安装启动交接.md`，让下一次任务无需重读完整对话即可理解本次故障、实现、环境状态和后续工作入口。

## 读者与结构

面向下一位接手本仓库的开发者或 Agent。文档采用“开头速查摘要 + 完整交接正文”：

1. 一分钟速查：当前服务状态、访问地址、默认端口映射、两个入口脚本和 Windows 登录任务。
2. 原始问题与根因：区分容器 `Created`、未监听 5000，以及 Windows 保留范围 `4910–5009` 的更深层原因。
3. 最终决策：前后端分离、只管理 Docker 后端、默认宿主机 5800/容器内部 5000、A/B 交互和非交互安全边界。
4. 实现清单：逐个说明新增或修改文件的职责，不复制大段源码。
5. 脚本行为：安装模式、启动模式、端口冲突分类和开机自启动流程。
6. 当前机器状态：Compose 服务、API 地址和计划任务；明确这些是 2026-09-13 验证时状态，下一任务必须重新检查。
7. 验证记录：宿主机、Android 模拟器、普通进程冲突、Docker 容器冲突、Windows 保留端口、非法输入和非交互日志。
8. 提交记录：按顺序列出本任务相关提交及用途。
9. 已知限制和后续首检：未通过卸载 Docker Desktop 模拟全新机器；公网 HTTPS、防火墙和自定义端口需按部署环境复核。
10. 常用命令：提供无破坏性的状态、日志、API 和计划任务检查命令。

## 安全与准确性

- 不写入或回显 `.env` 中的数据库密码、JWT 密钥、加密密钥或初始化令牌。
- `serverId` 不是凭证，但交接无需记录其具体值，只记录已验证稳定返回。
- 明确当前仓库仍有用户原有的未提交前端改动，本任务未修改、暂存或提交这些文件。
- 不把验证时状态描述为永久事实；所有运行状态附带复查命令。
- 文档内路径、脚本名称、提交哈希、端口和命令必须来自当前仓库及实际验证结果。

## 验收

- 下一任务仅阅读该文档即可找到两个入口脚本、共享实现、测试、设计与实施计划。
- 能明确回答“为什么 5000 失败”“为什么改成 5800”“A/B 分别做什么”“开机启动如何工作”。
- 能用文档命令重新验证容器、API、Android 局域网访问和 Windows 计划任务。
- 文档中不存在真实秘密值、占位符或与当前实现矛盾的描述。
